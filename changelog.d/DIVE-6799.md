## Unreleased — feat(self-update): nightly updates on a self-hosted box, off by default, one switch to turn on (DIVE-6799)

`sudo 5dive self-update --on` installs an hourly timer that updates the box at
night; `--off` removes it; `5dive self-update --status` says whether it is on and
what the last run did. Off by default: the installer, and a manual
`5dive self-update` on a box where it is off, now end with one line,
"Recommended: turn on nightly updates with 5dive self-update --on". The pasted
root-crontab advice is gone.

With it on, a box takes a version only after it has seen 5dive's fleet route
serve that version for 24 hours (the managed fleet goes first), installs it
between 01:00 and 06:00 local time, and on a run with nothing new installs and
restarts nothing, so agents keep their live session. Restarts go through the
existing predicates: only agents whose payload moved, and a busy agent waits for
its next idle moment. A failed update keeps the version the box had and is not
retried until the next night. `--on` refuses on a box 5dive built
(`/etc/5dive/provisioning.env`), which update.sh already updates.
