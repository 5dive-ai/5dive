## Unreleased — fix(agent): an agent can no longer give itself root or admin with `agent grant` (DIVE-7982)

An admin seat holds the 5dive CLI as root, and `sudo 5dive …` runs as root, so
`sudo 5dive agent grant <itself> root` used to work: admin was root one command away.

- `agent grant <name> root|admin` now refuses when the caller is an agent seat, and
  writes nothing. The caller is read from the uid sudo records, never from `$SUDO_USER`.
- Root, the box owner's login (`claude`) and any human login under sudo work as before,
  with the same output.
- An agent can still take itself DOWN to `standard`, and a seat that already holds
  unrestricted root is not refused (it widens nothing).
- Checked every other writer of sudoers, root units and root cron: `agent grant root` was
  the only one a caller could aim at root. `agent create --isolation=admin` stays as is
  (a new seat no wider than an admin caller, and the default for every hire).
