## Unreleased — fix(account): `account list` and `account usage` stop spawning a process per field (DIVE-6985)

Both back the Telegram /account picker, and on poke-two they took 1.5s and 1.8s,
almost all of it in spawned processes rather than work. `account list` forked once
per runtime type and ran a grep per env var for every account (~23 spawns each),
then ~10 more per signed-in type for the sign-in tile. `account usage` read the
registry twice per account and again per seat, ran five jq calls and two sqlite
calls per account with a live reading, and rewrote `usage.json` even when nothing
had changed.

Now `combined.env` is read once with shell builtins, a type with no
`<profile>/<type>/` folder is skipped before any fork, the tile's JSON is built
without jq where the values are plain, and the usage rows come from one registry
read, one jq join and one batched sqlite write. Output is byte-identical to the
old code on a 16-shape fixture (list) and a 21-seat fixture (usage, two passes).
`tests/account_read_spawns_unit.sh` pins the replaced grep semantics and the call
counts (pre-fix tree: 7 sqlite, 64 jq calls; now 3 and 20).
