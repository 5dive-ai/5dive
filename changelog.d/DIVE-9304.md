## Unreleased — fix(supervisor): a restarted agent is no longer reported stuck (DIVE-9304)

After `sudo 5dive agent restart <agent>`, the very step the supervisor recommends,
`5dive supervisor` kept naming the agent `composer-wedged / submit-unverified`, with a
growing age, until some later wake happened to send it a message. An agent with no task
is never woken, so the false "stuck" lasted forever. The restart had already thrown the
stuck message away.

Now `agent restart` (plain and `--defer`), `agent start`, the agent's own restart and
`agent rm` clear that mark, and the supervisor ignores a mark written before the agent's
service last came up, so a restart by any route (a reboot, systemd's own restart) clears
it too. An agent that is still stuck after the restart is marked again by the next
message that cannot be sent, so a real problem is still reported.
`tests/wedge_mark_restart_unit.sh` covers each verb, the age filter, and two mutation arms.
