## Unreleased — feat(agent): `agent mail set|remove|list|show` connects a mailbox to an agent for the himalaya CLI (DIVE-5161)

A partner client with no terminal can now give an agent a mailbox with an app password. 5dive-api runs
`5dive agent mail set <agent> --email= --imap= --smtp= [--caldav=] --password=- --json` over the exec
tunnel. The password is read from stdin only; `--password=<value>` and a terminal on stdin are refused.
The verb installs the pinned, sha256-checked himalaya v2.1.0 binary, and it checks the login as the
agent against a throwaway config before it saves anything. A failed login returns `login_failed:` (rc 6)
and an unreachable server returns `mail_unreachable:` (rc 3).

On success the agent's own 0600 files hold the password, the himalaya config, a CalDAV netrc (only when
the calendar answered) and a secret-free `mail.json`. The agent's instructions file gets a `5dive:mail`
block that says how to read mail and that it must never send, reply, forward or delete without the
client's explicit yes. `set` and a `remove` that removed something schedule a deferred restart of the agent
(reported as `restarted`), because a running seat reads its instructions only at session start. `remove` undoes all of it, a foreign himalaya config is never overwritten or
deleted, and `list`/`show` report `{agent,email,calendar}` and never a secret.
