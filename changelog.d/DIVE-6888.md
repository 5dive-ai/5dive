## Unreleased — fix(agent-list): a codex agent with no model set reports the one it runs (DIVE-6888)

`5dive agent list` listed a codex agent whose `config.toml` names no model as `model: null`,
and the fleet snapshot (the path every production `agent list` takes) had stopped reading
codex's `model_reasoning_effort` at all. The app's chat ⋮ menu now names the agent's model, so
a blank there left "what model is it on?" unanswered — the question that started this.

Codex effort is read from `config.toml` again, the same way the shell resolver reads it. When
no model is set, two new fields, `liveModel` and `liveEffort`, report what the agent's live
thread runs, read from the dispatcher's health file the same way telegram-codex's `/status`
reads it. Both are null when the model is set or the health file names none.

`tests/agent_list_batch_unit.sh` and `tests/codex_config_parity_unit.sh` cover the snapshot
and the shell loop; their new arms go red with the change reverted.
