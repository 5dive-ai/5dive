## Unreleased — fix(agents): close the browser at turn end, so a leaked Chrome can no longer hold a finished seat at `busy` (DIVE-4306)

`agent-browser` launches a headless Chrome tree and does not close it when the turn ends. Claude
Code reports native status `busy` for as long as ANY background shell is alive — that is what the
"N shells still running" suffix on a finished turn's done line means — so the heartbeat's idle
check saw `busy` and the seat took no work. Measured 2026-09-11: quinn carried an
`agent-browser-linux-x64` plus its Chrome tree for 1h20m past the grading turn that opened it, and
was undispatchable that whole window; lodar found it by eye and main killed the tree by hand.

DIVE-4298 bounds the damage at the heartbeat (classify idle-with-background-shells, reap on the
done line). This closes the leak itself, so there is nothing left to bound: a new `Stop` hook,
`stop-browser-teardown.sh`, runs `agent-browser close --all` at end of turn and reaps anything that
survives it — uid-scoped, matched on the path-shaped token every process in the tree carries, TERM
then KILL. It never blocks the Stop (always exits 0).

Wired at boot by `5dive-agent-start` rather than at agent-create: the leak is on seats that already
exist, and every seat runs the boot script on every restart, so one restart backfills the whole
fleet. The merge is idempotent and additive — an existing `Stop` array (the telegram plugin's, say)
is appended to, never replaced.

A turn that needs the browser to outlive it writes an expiry epoch to `~/.5dive/browser-lease`;
while that is in the future the hook is a no-op. The lease is an expiry rather than a flag, so a
forgotten one self-heals and DIVE-4298's reaper stays the backstop.
