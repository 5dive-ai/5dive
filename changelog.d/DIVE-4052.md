## Unreleased — fix(supervisor): the quota-exhausted FLEET-HEALTH alert is now off by default on BOTH legs (DIVE-4052)

Hitting a usage limit is how a subscription behaves, not an incident. The supervisor treated it as
one and told two audiences about it: a Telegram push to the paired human, and an `agent send main`
into the lead's accumulating session — where each one costs a full turn that re-sends the whole
window. Measured on `supervisor_events` (`event='alert' AND classification='quota-exhausted'`):
**47 in the seven days to 2026-09-08.**

Both legs now sit behind one opt-in sentinel, `${STATE_DIR}/supervisor.quota-alerts.enabled`
(`_SUP_QUOTA_ALERTS_FLAG`). Absent — the default — a quota wall produces **the audited
`supervisor_events` row and nothing else**: that row is the record, it is queryable, it keeps the
DIVE-3272 cover, and it costs no turn. Present, both legs fire on every shape, unfiltered, so the
class stays available as a debugging mode. One flag, not two: a mute that only half-applies is the
noise it was meant to remove.

Deliberately unchanged:

- **`verify-challenge` stays loud on both legs.** An ID/age-verification challenge is account state
  only a person can clear. It is not a quota wall and must not be swept up in this.
- **`no-output` keeps its machine leg.** DIVE-3982 muted its human leg only; that split is correct
  and this change does not touch it.

DIVE-3970's episode-expiry escalation is **retired**, not flag-gated. It existed solely to un-mute a
wall that outlived its promised reset, so with the class muted unconditionally it had no human leg
left to restore. It was also wrong on a shared auth profile, which walls every 5h window: the
episode chain never breaks, so on 2026-09-08 it announced `STILL WALLED 81h … this is now a hard
wall` about a pane the same line quoted as `continuing automatically at 5pm`. The per-shape
apparatus it was built on (`_sup_quota_selfheal`, the horizons, `_sup_quota_escalate_after`,
`_sup_quota_episode_first`) goes with it, because every branch now returns the same answer and
callerless machinery is the dead code this row warned against. `_sup_quota_deadline` **survives** —
DIVE-3880 classification and the quota-lapsed disarm both read it. A retirement note stands where
the apparatus was.

This is `5dive-cli`, which does not auto-deploy: merging changes nothing on a box. The alerts stop
when a release cut lands and `/usr/local/bin/5dive --version` on the host shows the new tag.
