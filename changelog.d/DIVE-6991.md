## Unreleased — fix(team): give an imported team one shared folder for handing over files (DIVE-6991)

Every seat's home folder is its own, so a file one teammate made was a file the next one
could not open. In a four-team test the marketing team fell back to `/tmp` to pass images
around, at about six extra rounds and two messages to the owner. Text goes in a message; an
image or a video cannot.

`5dive team import` now makes one folder per team at `/var/lib/5dive/teams/<slug>/handoff`,
owned by a new group `team-<slug>` (setgid, 2770). Every member joins the group and also gets
a named access entry, so a seat that is already running can use it without a restart, and a
file made with a strict umask stays readable to the rest. Each member's instructions name the
path once (a re-import adds no second note, and a team imported earlier learns it on its next
import). `team ps` prints it (`FOLDER` line, `.folder` in `--json`), and `team leave` takes
both the access and the note back. A bare `5dive up -f` is unchanged.

`tests/team_import_handoff_folder_unit.sh` drives a slug import through the real `team import`
with the OS calls recorded (21 arms; 19 red on the pre-fix tree). Its root arm, run by CI's
`root-arms` job, makes two real users: one writes a file under umask 077, and the other, whose
process started before the folder existed, reads it and writes to it.
