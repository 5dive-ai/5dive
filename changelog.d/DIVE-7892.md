## Unreleased — fix(agent-start): Claude seats compact at 400k context, not ~950k (DIVE-7892)

A Claude seat now launches with `CLAUDE_CODE_AUTO_COMPACT_WINDOW=400000`, so it compacts its
conversation near 400k tokens instead of waiting for Claude Code's own ~95% of a 1M window.

On one customer box an agent went silent for about 35 minutes: four replies in a row filled the
64k output cap with a single repeated word, all at 632k–831k context, until the native compaction
fired at 950k and the seat recovered at once. 400k sits under the lowest context the loop was seen
at. Existing seats pick it up on their next restart.

The owner's own choice still wins. The environment variable beats Claude Code's `autoCompactWindow`
setting, so the default is exported only when the seat has none of its own: no value already in the
unit's environment, and no `autoCompactWindow` (top-level or per model, which is where
`/autocompact` saves), or `env.CLAUDE_CODE_AUTO_COMPACT_WINDOW`, in the user, project or managed
settings Claude Code reads for the seat. A window set later with `/autocompact` takes over at the
next restart.

`tests/claude_compact_window_unit.sh` runs the start script's own type case: 17 arms, three of
them red on the script before this change.
