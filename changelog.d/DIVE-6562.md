## Unreleased — fix(task): a closed PR whose work landed closes on its recorded merge proof when main can't be read (DIVE-6562)

A row whose pull request landed as a direct commit reads CLOSED with no merge, and the
done gate's CLOSED-unmerged branch accepted it only on a subject scan of main. From a
seat that cannot read main that scan comes back empty, so the close was refused, and the
recorded merge proof (`task verify --merge-proof`) was never consulted because the PR
state itself was answerable. `--force-merge-gate` did not reach that branch either, so no
seat could close the row (hit on DIVE-6554).

When the PR reads CLOSED and the scan is unreadable (empty — not a measured 0 and not
`bound:*`), the gate now accepts a merge proof stamped against the row's current binding,
with the `task.merge-proof-close` audit line and a warning naming the unread scan and the
prover. A measured 0, a `bound:*` answer, a stale proof and an OPEN PR still refuse.

`tests/task_merge_gate_foreign_and_landed_unit.sh` cases B5a–B5f cover each arm; the
unfixed `status.sh` fails B5a, and dropping either the empty-scan or the CLOSED test turns
the matching refusal arms red.
