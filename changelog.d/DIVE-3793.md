## Unreleased — fix(agent-start): a cold-start kick that is never TYPED now reports itself (DIVE-3793)

DIVE-3791 made the cold-start kicks report "typed but never sent". The other half stayed
silent: each kick block polls the pane for its fork's ready marker in a bounded window and
single-fires, and when the marker never appeared the `for` loop simply ran out — no `warn:`
line, no breadcrumb, no journal line. The agent was parked and not listening, and nothing
anywhere said so. That is the same invisible shape as the outage DIVE-3792 was filed for:
2h40m deaf on a customer box with every health signal green.

All three blocks (grok, antigravity, codex) now record how they left the poll loop and report
the exhausted window through a new `coldstart_kick_never_typed`, which writes the same
`~/.5dive-coldstart-kick-failed` breadcrumb and a `warn:` line that `coldstart_kick_submit`
writes on a failed submit.

The two messages deliberately share no phrase. "Typed but never sent" is a wedged TUI that
swallowed an Enter; "never typed at all" is a fork that never reached its ready state — most
often an unauthenticated login screen or a boot slower than the window. Different faults,
different next steps, and whoever holds one breadcrumb has to be able to tell which they have.

A third message covers the `capture-pane` failure path, which `break`s out mid-window and so
lands in the same arm: it says the pane could not be READ rather than claiming the marker was
absent, because there the marker may well have been showing and we were blind to it.

The already-listening exit is not a fault and does not report one — if the plugin's
server-side inbound kick armed the listen loop first, codex breaks out having typed nothing
and stays quiet.

`tests/rearm_loop_regression_unit.sh` grades this per block, not once: section 3 requires each
block to declare the warn, to mark a landed kick as typed (a block missing that mark cries
wolf on every healthy boot), and to separate an unreadable pane from an absent marker.
Section 5 then runs the three real block loops against the scripted tmux stub — an exhausted
window, an unreadable pane, a healthy boot, and codex's already-listening pane — because a
warn that exists in a function no loop reaches is the silent failure with extra steps.
