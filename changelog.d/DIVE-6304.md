## Unreleased — fix(plugin): `plugin upgrade` moves each Claude seat to the new plugin version and reports the version it actually has (DIVE-6304)

`5dive plugin upgrade` re-registered each Claude seat with `claude plugin install`. Claude Code
treats that as a no-op when any version is already installed. So a seat stayed pinned at the old
version, and its agent kept loading the old skills, while the upgrade printed
`<seat> (claude): <plugin> registered`. Measured on a box upgraded to browser 1.41.0: one seat
was still pinned at 1.39.0 after the upgrade and was running the old skill text.

A seat pinned below the box's version now gets `claude plugin update`. The pin is then read back
from the seat's `installed_plugins.json`, and the line reports it: `re-pinned 1.39.0 -> 1.41.0`.
A seat that still did not move says `is still pinned at 1.39.0 — the box has 1.41.0`, counts as
failed, and never prints "registered". A seat whose running session still has the old version
loaded is named, along with the `5dive agent restart` command that loads the new one. The
upgrade does not restart a seat itself, because a restart drops its in-flight turn.

The nightly `5dive-refresh-plugins.sh` logs `repin <key>: <from> -> <to>` for every pin it moved,
and `STALE <key>: pinned <v>, box has <b>` for a seat still below the box's own record. A STALE
seat is counted in `refresh_failed_count`.
