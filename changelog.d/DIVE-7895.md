## Unreleased — fix(agent-config): a wrong model id no longer leaves a Claude seat dead (DIVE-7895)

`5dive agent config <seat> set model=<id>` used to check only the characters and write any id
into the seat's settings. A wrong id failed every turn with `model_not_found`, and every restart
booted back into it, so only a root edit of the settings file brought the seat back.

The set now checks the id against the account the seat will run on:

- **A Claude login** (a bound Claude account, or an unbound seat on the box's own login) refuses
  anything Anthropic can never serve and writes nothing. It accepts the family aliases
  (opus, sonnet, fable, haiku), Claude Code's own aliases (default, best, opusplan) and any
  `claude-*` id. A `claude-*` id this CLI does not know yet is accepted with a warning, so a new
  release still works.
- **Any other account** (OpenRouter, your own AI, Bedrock, Vertex) accepts any id. One that is
  neither a known Claude model nor the account's own tier id prints a warning with the exact undo
  command.

The model a set replaces is kept in the registry as `modelPrev`, so the undo is one command.

`tests/agent_config_model_guard_unit.sh`: 31 arms, 14 of them red with the check removed.
