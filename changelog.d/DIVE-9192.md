## Unreleased — fix(task): `task done` closes a row delivered with a commit URL once it has landed (DIVE-9192)

On a repo where agents push straight to main, a row is bound with
`task deliver --pr=https://github.com/<owner>/<repo>/commit/<sha>`. After the verifier
PASSed and `task merge-landed` recorded the sha on the default branch, `task done` still
refused: "gh could not read <commit url>, so the merge is UNKNOWN". The close gate asked
`gh pr view` about a commit, which never answers.

- The close gate now reads a commit URL with the same landing check `merge-landed` uses:
  on the default branch closes, not on it refuses with the reason ("not on main
  (compare: diverged)"), and an unreadable forge refuses and points at `merge-landed`.
- A `graded-sha:` in the result is compared against the landed sha instead of being
  reported as not checked.
