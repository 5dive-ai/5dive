## Unreleased — fix(security): a standard seat's dashboard chat works again, and still cannot read the box token (DIVE-5894)

DIVE-5690 closed `/etc/5dive/connectord.env` to standard seats and moved what they did with the
box identity to root. It missed one reader: the dashboard chat adapter, which runs as the seat and
read the token itself. From the first nightly on 0.78, that adapter exited at boot on every
standard seat. Claude seats lost dashboard chat with no visible sign, and a Codex seat with the
dashboard channel never took a turn, because its dispatcher died with the adapter.

- **New root rail `5dive _dashboard_relay`**, granted to every standard seat by one exact-path
  sudoers line with no arguments (`render_standard_sudoers`). The operation travels on stdin:
  `ping`, `pending`, `ack <id>...` or `event <chat_id> <text> [file]...`. Root derives the seat
  from the sudo caller and makes it the agent of every call, builds each body with jq, and posts
  to one of three fixed control-plane URLs. It prints the control plane's status and body. The
  token never reaches the seat, and is re-read on every call, so a rotation needs no restart.
  It never touches curl's command line either, which any seat can read from `/proc`: the
  bearer goes in on curl's stdin and the body from a root-only temp file (the DIVE-5168 rule).
- **A seat acts as itself only.** An ack may name only ids that this seat's own `pending` poll
  was offered (kept root-only in `/var/lib/5dive/dashboard-relay/`), because the control plane
  scopes a DM ack by owner, not by agent. A reply file must be a regular file directly in the
  shared chat-downloads folder when the reply is posted. That is checked once: the download
  is served later by shelld as `claude`, which follows symlinks under /home, so what a seat
  can point the owner's download at is what `claude` can read (the owner's own file browser
  already reaches the same set), and it reaches the owner, not the seat.
- **Existing seats get the line on upgrade** through `agent _reconcile_sudoers`, and the grant
  classifiers and the builtin-verb list know it, so a re-rendered seat still reads as standard.
- Needs dashboard 0.4.5 / telegram-codex 0.5.34 from 5dive-plugins, which use the rail when the
  token file is unreadable and keep a Codex dispatcher up when an adapter exits.

Not changed: admin seats and `claude` still read the token directly. `agent info` still suggests
a restart for a dispatcher whose dashboard adapter is down.
