## Unreleased — fix(heartbeat): a seat with no memory store is no longer counted as "could not run", and doctor names a seat whose consolidation pass never ran (DIVE-6287)

The six-hourly memory-consolidation sweep visits every seat with a unix user, including codex and
opencode seats, which have no Claude memory store. Those seats answer `not_found: no memory store`,
and the sweep counted that as "could not run", with no seat named. On one box the counter read 1
for 24 days, so a real lapse on a Claude seat (a lost sudo grant, a timeout) would have shown only
as 1→2. Meanwhile `5dive doctor` said "every enrolled seat's last consolidation pass reached the
model", because it only read the API-refused counters, and a pass that dies before the API leaves
none.

- The sweep counts a no-store answer in its own `N no store` bucket. It matches the class AND the
  message: `not_found` is also what a seat with no claude CLI answers, and that one stays
  could-not-run.
- Every could-not-run is logged by name with its reason:
  `[memory-consolidate] could not run: <seat> (<reason>)`.
- The sweep writes a `<seat>.norun` marker (consecutive passes, reason) next to the cadence stamp,
  and a `<seat>.nostore` marker. A pass that parses deletes both. They are reaped with `.notx` when a
  seat is gone, and `agent rm` deletes them.
- Doctor warns and names every seat with a `.norun`. With only no-store seats beside healthy ones it
  stays ok, and the ok names the skipped seats instead of claiming every seat reached the model.
