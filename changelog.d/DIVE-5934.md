## Unreleased — feat(tool): AWS keys and a Google sign-in for every agent (DIVE-5934)

`5dive tool set aws` saves an IAM access key pair (`AWS_ACCESS_KEY_ID`, then
`AWS_SECRET_ACCESS_KEY`, on stdin), and every agent's aws CLI and SDKs read it from their next
command, like the other tool keys.

Google has no key to paste, so it is a sign-in. `5dive tool google start` runs
`gcloud auth login` (with Drive access) once, as `claude`, against the gcloud config every agent
already shares. `poll <session>` returns the Google link to open, `submit <session>` takes the
code Google shows (on stdin, never argv), and `cancel <session>` stops it. If gcloud is not
installed yet, `start` installs it in the background first (state `installing`). It refuses when
`/usr` has less than 1.5 GiB free. `5dive tool rm google` signs the box out.

`tool ls` now ends with `{"id":"google","kind":"signin","env":[],"connected":…,"account":…}`, read
from gcloud's own files without running gcloud, and every key tool's row carries `"kind":"key"`.
