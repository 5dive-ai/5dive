## Unreleased — fix(task): `task merge` merges a companion PR named only in the result (DIVE-6922)

A row can bind a second pull request three ways: `task deliver --pr= --pr=`, a pull URL
in its result, or one under the body's "Delivered as". The close gate checked all three.
`task merge` checked only the first, so a row whose companion was named in the result
saw its primary already merged, reported `already-merged`, and left the companion open
while the close gate kept demanding it: neither could finish.

`task merge` now reads the same set as the close gate, merges every open companion
first, then the primary. `tests/task_multi_pr_delivery_unit.sh` arms C1-C6 and M4 cover it.
