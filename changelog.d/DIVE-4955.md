## Unreleased — fix(plugin): `official` is decided by where a plugin came from, not by its own manifest (DIVE-4955)

`plugin add` and `plugin upgrade` used to take a plugin's trust tier from the
plugin's own `plugin.json`, so any GitHub repository that wrote
`"fivedive":{"trust":{"review":"official"}}` installed box-wide — the "third-party
plugins are not open yet" refusal was one field away from anyone who read it.

A plugin is now `official` only when its marketplace was registered from a GitHub
repository owned by 5dive (`5dive-ai`, or the older `5dive-com` name), or is the
registry an operator pinned with `FIVEDIVE_PLUGIN_REGISTRY`. Everything else —
another owner, a fork of one of ours, a local directory, a stranger's repo added
under the name `5dive-plugins` — is `community` and refused, whatever its manifest
claims, with a sentence saying a plugin cannot vouch for itself. The manifest can
still lower its own tier: a 5dive-ai plugin marked `unreviewed` stays refused.

The tier stored in `installed.json` and shown on the consent screen is the decided
one, `upgrade` rewrites it, and `plugin setup` re-decides a record written before
this release. `5dive-ai/5dive-voice`, `5dive-council`, `5dive-ui` and
`voice@5dive-plugins` install exactly as before.
