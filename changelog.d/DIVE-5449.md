## Unreleased — fix: admin-tier agents hire catalogue agents themselves; standard agents keep the hire link (DIVE-5449)

lodar, 2026-10-03, to an admin agent: "can you hire dario to do website". It sent the hire link, and
when asked to do it itself it refused, saying the hire "starts billing, and only your tap can approve
that". Neither was true. On a box that is up, the Mini App's Hire is exactly `agent import <slug>
--as=<name> --isolation=<seat> --auth-profile=<the owner's signed-in account>`; Stars are sold only
when there is no box yet. The box instructions still sent every catalogue hire through the owner's tap.

The `5dive:hired-agents` block now tells an admin-tier agent to hire with
`sudo 5dive agent import <slug> --as=<name> --auth-profile=<claude account in 5dive account list>`,
adding `--isolation=admin` for a Leadership, Engineering or Ops pack (the Mini App's seat rule).
It also names the one thing that still needs the owner: the new agent's own Telegram bot, through
Connect on its row in the Mini App's Team tab. Without `--auth-profile` an import binds the agent to
its own empty login, which never answers. A standard-tier agent still sends `5dive hire-link <slug>`.
The block stays within the 450-word cap. `hire-link --help` and `5dive --help` now say which tier
the link is for.
