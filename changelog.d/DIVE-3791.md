## Unreleased — fix(agent-start): cold-start kicks now verify their own Enter (DIVE-3791)

`5dive-agent-start`'s grok and antigravity cold-start kicks typed a kickoff prompt
into the fresh TUI, slept, fired `Enter`, and discarded the result — directly under
a comment saying the TUI "occasionally drops a folded Enter". When that Enter went
nowhere the agent sat at a prompt it never left: nothing listening on Telegram, and
a boot that reported success. This is the `5dive-cli` half of DIVE-3786, which fixed
the same defect on the re-arm path in `5dive-plugins` (PR #46); it was named twice as
needing its own row and never got one.

Both kicks now go through one `coldstart_kick_submit`, which sends `Enter` as its own
call and compares the pane before and after — a landed Enter clears the composer and
starts a turn, so byte-identical panes mean the keystroke went nowhere. It retries
**the Enter only**, never the text (retyping would concatenate onto the stranded
line, which is the append half of DIVE-3786), and on a second failure writes
`~/.5dive-coldstart-kick-failed` plus a `warn:` line naming the real state instead of
leaving the boot silently wrong. A pane it cannot read counts as unconfirmed, never
as fine.

Both kick strings also still carried the two recursive-loop instructions DIVE-1180
removed for making the model self-loop on an empty inbox — because
`test/rearm-loop-regression.test.ts` scans the **plugins** repo and cannot see this
one. The text is now a single `COLDSTART_KICK_TEXT` constant with the corrected
"END YOUR TURN" phrasing, and the ban is ported to this repo as
`tests/rearm_loop_regression_unit.sh`, which also drives `coldstart_kick_submit`
against a scripted tmux stub and asserts the keystroke counts.

Unchanged and still true: `C-u`/composer-clear is verified against the codex TUI
only. No grok or antigravity agent exists on the build host, so neither fork's TUI
behaviour is verified in either repo — which is why this fix adds no `C-u` and the
retry re-sends only the submit.
