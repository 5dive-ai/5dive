## Unreleased — feat(offline-update): updates by disk trust an offline root key, with expiry and revocation (DIVE-7888)

An update file on a USB disk is signed by a key that lives with 5dive's build
system. Until now an office server trusted that one key directly, for good: if it
were ever stolen, a fake update would be accepted with no way to take the key back.

Servers can now also hold a second, "root" key that 5dive's owner keeps offline.
The root vouches for the signing key until a set date, and publishes a list of
keys it no longer trusts. A server that holds the root accepts a file only when:

- the root vouches for the key that signed it,
- that vouching has not expired (the refusal names the date and asks you to check the server's clock),
- the key is not on the root's list of withdrawn keys. The server remembers the
  newest list it has seen, so an older file cannot bring a withdrawn key back.

Nothing changes on this release: no root key is built in yet, so servers keep
checking files exactly as before. Files made from now on still install on servers
running older versions of 5dive.
