## Unreleased — fix(task): a close with nothing to check no longer prints a GitHub warning on a box without GitHub (DIVE-6808)

On a partner or customer box with no GitHub access, every agent's `task done` ended with
«close UNVERIFIED (no-gh-rail-for-listing)», and the agents repeated it to the owner as if
something were wrong. Measured on even-branch 2026-10-23: a team review and its close both
said the seat "has no GitHub access". Those agents never open a pull request, so there was
nothing for the merge gate to check.

Now, when the seat has no GitHub rail at all and the row names no repo, no pull request and
no branch of its own, `task done` prints nothing about the merge gate. The audit row is still
written (with `shown=no-subject`) and `5dive doctor --category=creds` still reports the
missing rail once. A row that names a PR, a `Repo:` line or its own branch still prints the
warning, and so does every seat that has a rail and could not finish its scan.

`tests/gate_gh_nocred_rail_select_unit.sh` covers the quiet close, the reading `doctor`
keeps, and a PR-naming and a branch-naming close that stay loud; the quiet arm is red on the
pre-fix tree. Four sibling harnesses that asserted the old line on a nothing-named close now
name a branch, or assert the line is gone.
