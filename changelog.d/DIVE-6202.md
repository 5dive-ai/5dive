## Unreleased — feat(agent): a pack is an OpenAgent agent bundle, so `openagent import` reads it and `agent import` reads `openagent export`'s (DIVE-6202)

`5dive agent export --format=pack` now writes the open agent bundle format from the OpenAgent spec
(SPEC.md, "Agent bundle"). The manifest also carries `bundle_version`, `openagent`, `source_harness`,
`created_at`, `persona` and a sha256 for every member, and each skill's BODY travels under
`skills/<id>/` next to its source ref. `openagent import agent.tar.gz --to=hermes|openclaw|claude-code|codex`
lands the persona, the skills and the memory files in another harness. 5dive's own keys (config,
plugins, hooks, the memory mode) stay in the same manifest, and openagent carries them through a
harness and back unchanged.

`5dive agent import` now also reads a bundle written by `openagent export`. It has no `packFormat`,
so import adopts it: the persona moves to `persona.yaml`, the skills listed are the ones under
`skills/*/SKILL.md`, and its memory counts as `raw`, because it is a plain copy of a harness's memory
files that nothing distilled. A bundle whose members do not match their sha256 imports with a warning
naming them: 5dive-api rewrites a partner pack after export, so a changed byte alone does not prove a
forgery.

Import now refuses a pack holding a secret-shaped string, using the same tripwire export runs. The
signing key that a deploy-time persona carries on purpose is stripped out first and is not a
finding. A 5dive RAW memory backup still restores, with a warning, as it exports with one.
Distillation (`--memory=distilled`), `--approve-memory`, the leak scan and provisioning stay 5dive's
own features on top of the format.

`tests/pack_openagent_bundle_unit.sh` covers the staged skill bodies, the bundle manifest, the
adoption, the sha check and the import secret gate. With `OPENAGENT_CLI` set it also runs openagent
itself both ways: our pack into hermes and back out byte for byte, and openagent's bundle adopted here.
