## Unreleased — feat(local): the office chat serves on the firm's own name, with the firm's own certificate

`sudo 5dive local serve --domain=team.yourfirm.com [--cert=<file> --key=<file>]` serves the office chat page as https://team.yourfirm.com (port 443 by default) from the box itself, so a Private customer's people open the firm's own address and no chat passes through my.5dive.ai or api.5dive.com. The firm's certificate is checked before anything changes (right name, not expired, matching key) and is never swapped for a self-signed one on a later `serve`; without one, the self-signed certificate now names the domain too. The never-root chat user gets only the capability to bind port 443. `local pair` and `local status` show the new address, and `status` shows whose certificate it is and when it runs out. A port already held by another program is refused by name.
