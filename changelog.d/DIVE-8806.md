## Unreleased — feat(signing): the master key page can approve the office app key (DIVE-8806)

The master key page (`packaging/signing/root-key.html`) now asks which key the owner is approving: the update key (CLI updates, unchanged) or the office app key (the app an office server serves). An office app key is certified as `office-key.json` / `office-key.sig` with kind `5dive-office-app-key`, under the same master key and the same blocked-keys list, and the saved file for 5dive carries it as `office_key_json_b64` / `office_key_sig_b64`. The page refuses 5dive's update key as an office app key.

The kind is signed in, so the two keys cannot stand in for each other: a CLI update file that carries an office app key certificate is refused, even when the master key signed it and that key signed the file. A new test arm and mutant prove it.
