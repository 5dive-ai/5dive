## Unreleased — fix(merge-gate): a seat with the GitHub sudo grant but no bot credential is reported as having no rail, not as a transient scan failure (DIVE-6051)

An unbound `task done` on a seat that holds a blanket `NOPASSWD: /usr/local/bin/5dive *`
grant but has no `/etc/5dive/connectors/github-bot.env` scanned 0 of N repos and was
classed `scan-failed`: "often transient; the credential is not implicated". The
credential was the whole problem. The relabel to `no-gh-rail-for-listing` checked
whether the seat was *permitted* to use the gate bot, not whether the bot's credential
was there, which is the same mistake DIVE-585 fixed in the rail selection. It now
checks availability, so the close and `doctor --category=creds` say `no-rail` and that
the box owner provisions one. A seat whose bot credential is present, or whose token
cannot see the repos, is classed exactly as before.
