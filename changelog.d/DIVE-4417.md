## Unreleased — feat(grader): one PARALLEL grader PROCESS per delivery, dark by default (DIVE-4417)

The grader lane can now launch one headless one-shot **process** per delivery under the
pool seat's own account, instead of assigning and waking the seat's single running
session. A seat runs one session at a time, so N spawns onto a seat were an N-deep serial
queue; N one-shots are N graders.

Off by default: `_GRADER_SPAWN_MODE` ships as `session` and session mode is unchanged.
Naming `process` is a third deliberate lock alongside the dry-run default and the empty
pool, because each one-shot is a separate paid session with no per-seat queue in front of
it. In that mode the concurrency cap is counted from the **live process table** rather
than from lifecycle rows, so a slot returns the moment a grader exits rather than when the
row closes; each grade gets a `runs` record with a `<seat>#<n>` session id, its own working
directory and its own log; and the seat's main session is never handed a grading turn, so
its Telegram and agent-to-agent traffic is no longer blocked behind a grade.

Known gap while the mode is dark: a second concurrent process under one account has no
systemd unit and no tmux pane, so `agent logs`, the supervisor pane classifiers and the
liveness rails cannot see it yet.
