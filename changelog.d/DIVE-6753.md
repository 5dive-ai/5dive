## Unreleased — fix(task): a merge-conflict bounce after a PASS no longer uses up the last iteration (DIVE-6753)

`task reject --merge-conflict` is the merger's bounce for work that passed grading and only stopped
merging cleanly (a sibling merged first, a version collided). The row goes back to the maker with the
FIX line as before, but the bounce does not count toward `max_iterations`, so it no longer files a
"keep going, or drop it?" gate. The flag is checked against the row: the current delivery must carry a
PASS, and the caller must owe the merge or have graded it. A quality reject still counts and still
gates at the cap.
