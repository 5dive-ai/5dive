## Unreleased — fix(opencode): a seat reads its own config, so its model pin takes effect (DIVE-5620)

An opencode seat on an included-AI account ran as OpenCode's own default model ("Nano Banana Pro
Preview", a Gemini image model) instead of the account's model, and every model call failed. The pin
was written, but seats launch through a login shell that points `XDG_CONFIG_HOME` at the shared
config home, so OpenCode never read the seat's own `~/.config/opencode` (model pin and persona).
`5dive-agent-start` now drops `XDG_CONFIG_HOME` for opencode seats only, and `agent create` pins a
non-BYO opencode seat to the account's model, which covers the partner sysadmin install. Existing
seats pick the fix up at their next restart after the upgrade.
