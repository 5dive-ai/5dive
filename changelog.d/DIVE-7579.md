## Unreleased — fix(local): fully-local run 5 — office chat on the right network, panel adds agents and installs updates, updates refresh plugins and the office server, zero outside lookups (DIVE-7579)

The run-5 proof of a fully-local office box (two private networks, the model on one, staff on the
other, every outside packet dropped) failed on seven defects. All seven are fixed:

- **Office chat on the staff network.** `local-only on` served the page on the FIRST private
  address, which was the model link, so the office could not open it. The network the box uses to
  reach its saved AI server is now skipped; when the box still cannot tell, the chat is not started
  and the refusal names each address with its network and the `--addr=` to pass.
- **A failed panel action no longer kills the panel's root helper.** It writes its audit line and
  the page shows what failed (it showed "no answer").
- **The panel can add an agent in local-only mode.** `agent create --auth-profile=<your own AI>`
  (what the panel runs, and what `account add` prints) is accepted when every address that account
  saved is on the office network. Cloud accounts, outside addresses and new credentials are still
  refused. The panel adds the agent to the office chat.
- **Install an update file from the panel** (owner devices only). Settings → Update: pick the
  file on your laptop and install. The server streams it to its own folder, root copies it out and
  runs `self-update --from=` in a separate job, so a changed or other-key file is refused with the
  same plain message as the terminal, and the page shows the result.
- **Updates by disk refresh the shared plugins** (Codex dispatcher, dashboard adapter, grok, agy,
  opencode, pi). bun's hard links made each filtered extract fail (5 warnings per update); the
  installer now takes each plugin from the update's fully unpacked copy.
- **An update re-stages the office chat and panel server** (`local _restage`, run by the
  installer) and restarts it only when it changed.
- **Zero outside lookups.** The busy probe (`claude agents --json`, run by the heartbeat and before
  every update restart), the auth and quota probe and the memory distiller now carry the same quiet
  settings as the agents on a local-only box; `doctor --repair` no longer tries an internet install.

Also: an update no longer restarts an agent whose plugins did not change; the Settings row with no
state is fixed; the tab bar no longer shows on the "can chat, not manage" screen; devices are named
by browser and kind ("Safari on iPhone") or by the owner; Settings shows the headline and only what
needs attention, with the checked list one tap away.
