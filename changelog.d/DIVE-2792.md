## Unreleased — fix(cli): a wrapped tool's non-zero is reported as that tool's status, and an unfilable `5dive bug` report is spooled instead of lost (DIVE-2792)

A passthrough verb runs another program and hands back its exit status. `gh` and `journalctl` both
use non-zero to carry ORDINARY STATUS — `gh` exits 4 for "not logged in" and 8 for "checks still
pending", `journalctl` exits non-zero when the journal is unreadable. The silent-exit backstop
turned every one of those into *"5dive … exited N without reporting a reason. This is a bug in the
CLI, not a refusal … the command did NOT run to completion and its effect is UNKNOWN"* — false in
both halves for a read that had already printed its answer one line above, and expensive in the one
direction that costs most: it sends the operator hunting a CLI defect, and it trains people to
ignore the banner on the calls where it is true.

- **`5dive gh`** now carries `exit $?` in the dispatch table like every sibling passthrough arm.
  The status already reached the caller without it — that arm is `main()`'s last statement and
  `main "$@"` is the script's — so this removes a load-bearing coincidence rather than a live
  bug: one statement appended after `esac` would silently replace gh's status with that
  statement's. (The banner half of the `gh` defect was fixed under DIVE-3135; this pins it.)
- **`5dive agent logs`** was the second instance, found by sweeping every arm of the dispatch
  table rather than fixing the one the report named. It had both halves: in text mode
  `journalctl` was the last statement, so a legitimate non-zero reached the backstop and got the
  bug banner; in `--json` mode `journalctl | jq` reported **jq's** status, so the same failure
  exited **0** with an `{ok:true}` envelope holding zero lines. Now the status is captured, the
  envelope is only printed when the read succeeded, and a failure says whose status it is
  (`class:"passthrough"`).
- **`5dive bug --file`** files through `5dive gh issue create` — the exact route that is down in
  the failure this verb is invoked from, so a bug reporter's only path out was the broken one and
  the report was simply lost. An unfilable report is now written to
  `${XDG_STATE_HOME:-$HOME/.local/state}/5dive/bug-spool/` (0700/0600, the caller's own state dir,
  never root's) and the path is printed. It still exits non-zero — spooled is not filed — and
  **nothing ever drains that directory**: this verb's whole posture is that a human sees the bytes
  before they leave the box, and a self-draining spool would be that posture's exact inverse.

Graded end to end through the built bundle by `tests/dive2792_passthrough_exit_unit.sh`.
