## Unreleased — fix(team-bot): the team-bot listener passes only the owner's messages from the team group to an agent (DIVE-7972)

The shared team-bot listener runs as root and hands messages to agents that have sudo. It used to pass a message on when the sender was not a bot and the thread id matched an agent's topic. Nothing checked which group the message came from or who sent it. So anyone in the team group, or anyone who added the team bot to their own supergroup and posted in a thread with a matching number, could talk to the agent as if they were its owner. Now both checks must pass, or the message is dropped and the reason is logged: the chat must be the team group the agent's topic was registered in, and the sender must be on that agent's allowFrom for the group (falling back to the agent's own allowFrom). With no list at all, nobody gets through. The telegram plugin (0.5.138) runs the same check again before delivering.

`5dive agent telegram-access groups --answer=name|every` now stores `groupsOwnerOnly: false` instead of removing the key. That records that the owner opened groups on purpose. With the key absent, telegram 0.5.138 lets a new group in with its owners only. Choosing `name` or `every` also opens a group that this default closed.

`tests/team_bot_sender_gate_unit.sh` (11 arms, including a mutant with the chat check removed) and `tests/telegram_access_groups_unit.sh` (65 arms).
