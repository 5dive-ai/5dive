## Unreleased — fix(goal): a goal over the step checkpoint asks the owner, so it can start on a box with an org lead (DIVE-8721)

`goal add` filed the plan check for a goal over the step checkpoint (more than 6 steps by default) as a tier-1 decision, which routes to the org lead — but only the owner's approve can build a plan (`goal add --from-gate`). On any box with a lead the goal never started: the app's card stayed on "planning" and the partner's Start answered 409. The check is now filed the way the Tier-2 plan check already was (tier 2, `--needs=human_tap`), so it reaches the owner, `task ls --json` reports `needs_human: true`, and Start builds it. `objective replan`'s count checkpoint gets the same fix. A plan check already open on a box keeps its old routing; withdraw and re-run that goal to move it.
