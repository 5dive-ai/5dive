## Unreleased — feat(dashboard): the dashboard chat works on a chat-only self-hosted box, where nothing listens (DIVE-6816)

A box linked from my.5dive.ai/self-host as chat only runs no file server and takes no inbound
connection: the box calls out to the API, like Telegram polling. The root rail a standard seat's
dashboard chat crosses (`5dive _dashboard_relay`) gains what that needs. The sudoers line is
unchanged (same exact path, no arguments), so every seat that has the rail has the new ops.

- **`pending [wait]`** holds the poll on the API up to `wait` seconds (clamped to 25) until a
  message lands; curl waits 15 s longer. With no wait it is the same poll as before.
- **`fetch <path>`** pulls a file the owner sent in the chat and writes it where the message says
  it is, as the files API writes uploads: `claude:claude`, 0644, in a 0755 dir, renamed into place
  from a root-only temp file. The path must name one file directly in the caller's own
  `/home/claude/chat-uploads/<agent>/`; a traversal, another agent's dir or a symlinked dir is
  refused before any network call.
- **`put <path>`** sends a file the agent attached to a reply. It must be the caller's own copy
  in `/home/claude/chat-downloads/<agent>-…`, a regular file the calling seat owns. It is read
  once, through a descriptor that does not follow a link or wait on a FIFO, into a root-only
  copy, and that copy is posted, so a seat that swaps the file for a symlink after the check
  sends nothing.
- Both are capped at 20 MB, the API's cap. The bearer still rides curl's stdin, never argv.

Needs dashboard 0.5.7 from 5dive-plugins, which uses these on a box with `/etc/5dive/chat-only`.
