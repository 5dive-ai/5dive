## Unreleased — feat(disk): `disk sweep` also clears old Codex releases, leaked Chrome cache dirs and the pip cache (DIVE-6329)

chill-gorge's box alert said "I already cleared the caches that are safe to delete, and it is
still low" at 4% free, while ~7G of rebuildable files sat there. ops cleared them by hand
(DIVE-6326). The sweep now covers the same three classes, so that sentence stays true:

- `codex-releases`: old release dirs under `~/.codex/packages/<pkg>/releases/`. It keeps the
  release `current` points to, the newest one, any release a process runs from or holds, anything
  touched in the last hour and any name that is not a version. A package with no resolvable
  `current` is skipped. Measured on chill-gorge: 9 dirs, ~3.7G.
- `chrome-cache`: `~/.cache/tmp.*` and `playwright_chromiumdev_profile-*` dirs holding only
  `Default/` with Chrome's cache dirs in it. These are what the browser plugin leaked before
  1.42.1 (DIVE-6327). They get the same holder scan and old/live/young/unknown states as
  `chrome-tmp`. Measured on chill-gorge: 473 dirs, ~3.1G.
- `pip`: `pip cache purge` run as the user, never `rm`, and skipped while that user has a pip
  running.

Each class logs a `disk-sweep class=<x> freed_kb=…` line and honours `--dry-run`. Claude Code's
`~/.local/share/claude/versions` is not swept, because its installer already keeps only two.
`tests/disk_sweep_unit.sh` goes from 50 to 65 arms. 15 of them fail on the tree before this
change, including five mutation arms.
