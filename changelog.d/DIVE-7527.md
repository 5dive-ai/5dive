## Unreleased — fix(seat): a run of safety-filter refusals reads content-refused, not a stuck login (DIVE-7527)

When the AI's safety filter refused a seat's conversation turn after turn ("safeguards flagged this
message"), the box read it as a stuck login and told the owner to sign a working login in again,
which changed nothing. That run now has its own kind, `content-refused`: the owner gets one message
per seat per episode saying the login works and to restart the seat for a new conversation
(`5dive agent restart <seat>`). `agent list`, `agent info`, `agent auth status` and `agent ask`'s
timeout say restart, never sign in. A plain refused request still reads as a stuck login. Harness:
`tests/selfhost_head_agent_unit.sh` section C.
