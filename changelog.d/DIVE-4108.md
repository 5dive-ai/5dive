## Unreleased — fix(guard): `| grep -q` under `pipefail` reported the OPPOSITE of what it measured — the pre-push harness guard refused compliant pushes at random (DIVE-4108)

`grep -q` exits 0 the instant it matches and stops reading. On a producer with more than one pipe
buffer (64 KiB) still to write, that closed pipe kills the producer with SIGPIPE — status 141 — and
`set -o pipefail` promotes 141 to the whole pipeline's status. An `if !` then reads "non-zero" as
"no match", so the check answers the opposite of what it just saw. It is a scheduling race, so it
only bites on inputs big enough to lose it.

**Measured, 2026-09-08.** `scripts/harness-tree-guard.sh` — the pre-push guard that decides whether
a push leaves the machine — carried the shape verbatim. `5dive push DIVE-4052` was refused on
attempts 1 and 2 and succeeded **unchanged** on 3; six identical direct runs of the guard gave rc
`0, 0, 1, 0, 1, 1`, each failing run naming a 905-line file that sources the required helper at line
37. It surfaces after a merge from `origin/main`, because the hook scopes the guard to files added
relative to the remote branch head, so every large test file main gained since the branch point
reads as newly added.

**Swept, not spot-fixed.** All 50 sites in `scripts/` and `src/` where a pipeline under `pipefail`
ended in `grep -q` are rewritten. Producers already held in a variable become a herestring
(`grep -qE "$RE" <<<"$content"`); producers you would not want to buffer — `tail` over a log,
`find` over a directory, a `db` query, an array expansion — become process substitution
(`grep -q … < <(tail …)`), which removes the producer from the pipeline entirely so `pipefail` has
no status to promote. Six of the 50 had a producer that can routinely exceed 64 KiB; the rest were
scalars and short lists that could never lose the race, fixed because the shape is a trap for the
next editor.

The guard's predicate, the DIVE-2211 tree contract and the guard's scope are all unchanged — the
predicate was right and the plumbing was wrong.

**Regression arm.** `tests/harness_tree_guard_unit.sh` gained a 316 KB compliant harness run 20
times, which must never be refused, plus a same-size non-compliant negative control that must be
refused on all 20 — so the fix cannot be confused with making the guard blind on large files. The
existing scenarios all use small fixtures and, by construction, could never have caught this: the
input SIZE is the fixture. Graded against the pre-fix guard the arm fails 20/20; against the fixed
guard, 0/20.

Notable polarity note carried into the code: in a test arm this shape fails OPEN (an absence arm
reports "gone" while looking at the line); in a guard's `if !` it fails CLOSED (a false refusal). A
bare `if` is a hole; an `if !` is a nuisance. Sort a sweep by polarity, then by producer size.
