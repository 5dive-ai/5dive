## Unreleased — feat(team): agents offer their owner a 5dive bug report when 5dive blocks their work (DIVE-6639)

No box had filed a `5dive bug` report in a week, and a box's agent hit five 5dive defects
without reporting one: the owner forwarded them by hand. The verb was one line near the end
of the 5dive-cli skill, and nothing told an agent to use it. Worse, the team block's "can't"
rule taught an agent to record a 5dive failure as its own limit.

The managed team block on claude seats and the codex operating baseline now carry one rule:
when a `5dive` command fails or does the wrong thing and a second, different check confirms
it, tell the owner in plain words and offer to report it; only on their yes run
`5dive bug --what=... --verb=... --file --owner-approved`. Cosmetic issues are skipped, so the
owner is asked only about failures that blocked real work. Both blocks are refreshed on
existing seats at update. opencode, pi, antigravity, hermes and openclaw seats have no managed
instruction block yet and do not get the rule.
