## Unreleased — fix(chat): turning on encrypted chat no longer hides it from the agent (DIVE-7440)

`5dive chat e2e enable` locked `/etc/5dive` itself to 0700 along with the key folder, so the agent
could no longer see that encryption was on: it got the raw sealed message and its plain reply was
refused, and the chat went silent. Enable now locks only the key folder. A box already hit puts
`/etc/5dive` back to 0755 on its own (every minute's device sync, `chat e2e status`, the nightly
self-update, or `5dive chat e2e heal`), and only when a key folder sits under it. The dashboard
plugin (5dive-plugins 0.5.19) no longer reads "cannot see the key folder" as "off": it asks root,
and if it still cannot tell it holds the message and refuses to send a plain reply.
Harness: `tests/chat_e2e_unit.sh`.
