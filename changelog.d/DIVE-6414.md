## Unreleased — fix(agent): a timed-out scoped ask no longer claims a delivery failure, and a spooled send says queued on its audit row (DIVE-6414)

A scoped `5dive agent ask` (one standard seat asking another) that timed out always said "the question
marker was never seen in the pane at all, so this is a DELIVERY failure … (check the input-prompt warning
above)". That path only reads the window after the question's marker, so it can never see the marker, and
no warning is printed above it. It now says the question was delivered when the reply window opened, and
otherwise that delivery cannot be seen from the scoped path, naming the audit row to check and
`--allow-unfenced` for a seat that does not fence its reply. The direct path points at the input-prompt
warning only when it actually printed one.

A message spooled for a busy seat still exits 0, but its `agent _deliver` / `agent send` row in
`/var/log/5dive/agent-audit.log` now carries `queued=1 spool_depth=N`, so the log no longer reads the same
as a typed delivery. A scoped ask whose question was spooled now says "queued, not asked" with
`queued:true` instead of "unconfirmed". The queued receipt now says the spool drains on the heartbeat's
tick, minutes apart, not as soon as the seat goes idle.
