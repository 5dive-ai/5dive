## Unreleased — fix(push): `--open-pr` now mints a PR title that pr-title-lint can pass (DIVE-4423)

- The default PR title was `"DIVE-N: <task title>"`, which can never match the conventional-type
  rule the `title` required context enforces — so every pull request the delegated push path opened
  arrived title-red and froze the merge queue until a second seat retitled it by hand. Roughly
  eighteen auto-filed rows (DIVE-4165..DIVE-4320, DIVE-4422) were nothing but that retitling.
- The default is now taken from the branch's own commit subject **only when the range holds exactly
  one commit** — the sole case where that string is both what GitHub offers as the title and what
  `pre-push-rail.sh` has already graded against this same rule. On a multi-commit range (measured
  2026-09-13: seven of eight recent pull requests here carry two to four commits) the title is
  `<type>(<ident>): <task title>` with the type taken over the WHOLE range — `feat` if any commit
  declares one, else `fix`, else `chore` — so a `chore: wip` first commit can no longer describe a
  feature branch and demote its release cut. Both paths are capped at GitHub's 256-character title
  limit, the reuse path truncating the subject before appending the ident so the ident survives.
  Reusing a single commit's subject preserves the author's type. The author's conventional *type* is the one thing the mint must not invent: it decides
  whether `release-cut` cuts a minor or a patch (DIVE-4086), so defaulting everything to `chore`
  would silently demote every feature. It is also what GitHub offers, and what `pre-push-rail.sh`
  has already graded against this same rule before the branch could be pushed.
- The by-construction form satisfies the rule whatever the branch looks like. Either way the ident survives, so the merge gate's ident-match evidence still binds — it is
  APPENDED to a passing subject that lacks it, never prefixed, because the rule anchors at `^` and
  nothing added at the end can redden a passing title.
- The rule is EXTRACTED from `.github/workflows/pr-title-lint.yml` rather than copied, for the
  reason `scripts/pre-push-rail.sh` already extracts it: a second regex is a second author for one
  contract and its disagreement is silent. A rule that cannot be read is not a pass — with nothing
  to certify the subject against, the mint takes the by-construction form.
- `--pr-title=` is unchanged and still wins outright.
