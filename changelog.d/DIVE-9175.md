## Unreleased — fix(task): a named reviewer binds without a PR, and the reviewer's close runs the stored check (DIVE-9175)

A reviewer someone named on the row (`--review=<seat>` / `--verifier=`) now binds on a `verify=delivered-only` box: the maker's `task done` hands the row to that reviewer instead of closing it, PR or not. Only the box-default reviewer still defers to a delivery, and `verify=never` still caps everything. Before this, a report row filed with `--review=` closed on the maker's own done, so a hired team's "the maker is never the checker" promise held only on code rows.

On a row with a stored `--verify` command, the reviewer's `task done` now runs that check (or finds a stamped PASS of the exact stored command at the graded sha) and refuses the close on red, printing the output. Note for graders: the check re-runs in the closer's current directory unless the latest result is a stamped PASS of that exact command, so if you verified with a different `--cmd`, run the close from the PR checkout or run `task verify --no-done` with no `--cmd` first.
