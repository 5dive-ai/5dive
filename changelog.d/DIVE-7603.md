## Unreleased — fix(local): disk updates keep packages out of agent history, the panel keeps its install log, the guide's order works on two networks (DIVE-7603)

Small issues from the fully-local run-6 proof (DIVE-7578, PASS on v0.116.0). None reached
outside the office; each is fixed here.

**Packages stay out of the agent's history.** The first update from a file committed every
plugin's packages into each agent's plugin checkout: 41,682 files and 38 MB of history on a
checkout the box built offline. The update now keeps `node_modules/` out of that checkout
(a local exclude, never committed), takes out any an earlier update committed, and leaves the
packages on disk where the agent runs them. An update that changes nothing still restarts
no one.

**The panel's update keeps what it printed.** An install from the office panel kept only its
last three lines, so a "failed to stage" warning was lost. The whole output now stays on the box
(`/var/lib/5dive/panel-update/install.log`, root only), and the Update card shows its last
lines under "What the last install said", also after a reload. Before the verdict, the card no
longer promises that agents restart.

**No terminal flag in the panel.** A file that is not newer is refused in the panel in plain
words. Only `sudo 5dive self-update --from=` on a terminal names `--allow-downgrade`.

**The guide's order.** On a box with two private networks the office chat page picks the
office network only when the AI account is saved first. The guide now saves it before
`config local-only on`, and says how to start the page if it was done the other way.

Harness: `tests/dive7603_local_polish_unit.sh` (13 checks, 10 red on v0.116.0) and two new
arms each in `tests/self_update_offline_unit.sh` (red before).
