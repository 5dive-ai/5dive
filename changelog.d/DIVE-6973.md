## Unreleased — feat(secret): saved logins are encrypted on the box, hold a login + password (+ 2FA key), and show their last use (DIVE-6973)

A saved login used to be one plain value per name in `/etc/5dive/connectors/saved.env`.
Each value is now encrypted with a per-box key (`/etc/5dive/vault.key`, 400 root, made on the
first save; openssl AES-256), and the first saved verb of the new CLI encrypts any plain line
already there. The key never travels: `agent export` refuses a stage holding `vault.key` or a
`saved.*` file, so a team copied to a new box re-saves its logins there. Root on the box can
still read the key; the separate-account tip on the save page is the guard for that.

One item can now hold a pair: `secret link --save=<name> --pair` serves a page asking Login,
Password and an optional 2FA setup key, with the separate-account tip above the fields. The
browser fills each by field (`<name>.login`, `<name>.password`, `<name>.2fa`), and a bare
`<name>` still fills an old one-value item.

`secret saved ls --json` returns per item its fields, the login (not a secret), the site and
its last use; `secret _reveal`, the root hop the fill uses, appends `<name> <host> <agent> <utc>`
to a root-only usage file. No output, usage line or page ever holds a password, 2FA key or value.
