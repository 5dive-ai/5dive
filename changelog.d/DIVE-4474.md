## Unreleased — fix(release-cut): `_filter_dropped` drains its stdin, so a cut no longer dies on a broken pipe before it can tag (DIVE-4474)

No 5dive-cli release could be cut at all. Run 34794905130 (2026-09-14, an authorised manual cut for
DIVE-4471) correctly derived `v0.37.0 -> v0.38.0` and then died one line later:

```
/home/runner/work/_temp/....sh: line 552: printf: write error: Broken pipe
```

`_filter_dropped` is the right-hand side of `_DROPPED=$(printf '%s\n' "$runs" | _filter_dropped)`,
and on the lane-OFF path it `return`ed **without reading stdin**. That closes the pipe while the
writer is still writing; once `$runs` exceeds the 64KB pipe buffer `printf` takes EPIPE,
`set -o pipefail` promotes it, and the runner's `bash -e {0}` kills the step. Its sibling nine lines
up, `_filter_required`, already had the right shape (`cat; return 0`) — that asymmetry is the whole
bug and the fastest way to find this class.

**The trigger is the SIZE of the data, not the logic**, which is why it passed every arm and every
run for as long as main's check-run board fitted in the buffer, and then became permanent. The drain
is `cat >/dev/null` rather than a bare `cat` because on this path the function must emit nothing —
its stdout is the hotfix lane's skipped-checks list.

**The regression arms had to pin two things the existing 106 did not.** Every helper in
`tests/release_cut_guards_unit.sh` drives the extracted block with `bash -c`, i.e. **errexit off**,
while the real step declares no `shell:` and therefore runs under `bash -e {0}`. So the new section
runs the same shipped bytes under `-e`, against boards either side of the buffer, and it grades the
pre-fix shape as a mutant — asserting the CAUSE (SIGPIPE, or `write error: Broken pipe` when the
writer's SIGPIPE is ignored) rather than merely "not green", since an unrelated refusal would read
identically. The mutant-on-a-small-board arm is kept deliberately: it stays GREEN, which is the
measurement of why this shipped.

**Second, separable defect, same file.** The comment guarding the version-derivation block read
`DO NOT ADD set -e TO THIS STEP. It runs under set -uo pipefail on purpose`. The step does run under
`-e` — the runner supplies it — and a note added by DIVE-4153 twenty-five lines below already said
so while pointing "further down" at a block that had since moved above it. Both are corrected to say
what is actually true: `-e` is always on in the runner, and what must not gain an `e` is the step's
own `set` line, because `tests/release_cut_assign_unit.sh` evals those exact bytes outside the runner
where it would change the mutation grade. Under a genuinely `-e`-less shell this broken pipe would
have been a harmless empty capture.
