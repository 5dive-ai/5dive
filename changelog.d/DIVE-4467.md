## Unreleased — feat(plugin): `plugin setup` runs a plugin's one-time host step, so it no longer needs a terminal (DIVE-4467)

`plugin add` prints a plugin's `fivedive.setup.command` and deliberately does not run it —
a string from a manifest must never execute because the publisher said so, at install,
before the user has seen what they installed. That stays true. What it left behind was a
dead end for everyone who never opens a terminal: the box half of a plugin (Chrome plus a
root-created profile store for `browser`; ffmpeg plus a whisper venv for `voice`) never
arrived, so the plugin read "installed" and its verb reported MISSING forever.

    5dive plugin setup <plugin>[@<marketplace>] [--yes]

is the same step, started by the user. It reads the command out of the manifest installed
on THIS box, shows the publisher's hint and the exact line first, and runs that line and
nothing else. No caller can supply a command — there is no argument for one — which is what
makes it safe behind a dashboard button: the verb is the allowlist.

The setup DECLARATION is now recorded in `installed.json` at install, and the RUN (command,
when, who, exit code) after it, so a page can tell "no host step" from "host step not done"
from "host step failed" rather than telling every user, forever, to open a terminal.
