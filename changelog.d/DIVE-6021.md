## Unreleased — fix(install): the agent shell startup shim no longer fork-bombs a seat that runs a test with an `id` stub (DIVE-6021)

Every agent's `BASH_ENV` shim (`/usr/local/lib/5dive/tool-env.sh`) ran a bare `$(id -u)`.
Only bash reads `BASH_ENV`, and it reads it in every bash script, so a unit test that put a
`#!/bin/bash` `id` stub first on `PATH` re-entered the shim without bound: each level waited on
the next until the seat hit its task limit and its runtime died. The shim now reads bash's own
`EUID` (falling back to the absolute `/usr/bin/id`) and calls no PATH-resolved command. The two
tests that stub `id` also drop `BASH_ENV`, so they are safe on a box still carrying the old shim.

Reaches boxes on the next CLI cut. Until then, on a box with the old shim, run any test that stubs
`id` as `env -u BASH_ENV bash tests/<file>`. `tests/tool_keys_unit.sh` T13 covers it; the pre-fix
shim is red on three of its arms.
