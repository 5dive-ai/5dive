## Unreleased — fix(local): the office chat takes a renewed certificate by itself and warns 14 days before it runs out (DIVE-8611)

`sudo 5dive local serve --cert= --key=` copied the firm's certificate once, so after IT renewed it the office chat kept serving the old copy until it ran out and every browser refused the page. The box now remembers where the files are and checks them daily (plus a certbot deploy hook when certbot is installed): a renewed pair that passes the same checks as `serve` (right name, not expired, matching key, files only root can change) replaces the old one and the chat restarts on it; one that fails is not taken and the reason is logged. From 14 days before the served certificate runs out, the server's login message, `5dive local status` (text and `--json`) and a banner in the owner's panel say so, with the date. An update adds the daily check to an office chat set up before it; `serve --stop` removes it.
