## Unreleased — fix(liveness): a seat whose Telegram poll is stuck reads poll-stalled, not alive (DIVE-7825)

After a Telegram outage, a seat's poll for new messages could hang for about eight minutes. The owner's messages queued unread while the seat's heartbeat file stayed fresh (it beats on a timer) and `5dive liveness` said alive, because the seat had written a row recently.

The Telegram plugins (telegram 0.5.136 and the forks) now cut a poll off after its 30 s window plus 15 s, and write `bot.lastpoll` in the channel state dir each time a poll comes back. `5dive liveness` reads that file for every runtime's state dir: a running poller whose last poll is over 120 s old is `poll-stalled`. It outranks alive (only `quota-exhausted` ranks above it), exits 4, names the file and its age, and is counted in `summary.pollStalled`; the JSON record carries `telegramPoll`. No file (an older plugin), a poller that has exited, or a home this uid cannot read changes nothing.

`tests/liveness_poll_stalled_unit.sh` (14 arms) seeds throwaway homes and a fake proc root: stale with a live poller, fresh, absent, stale with an exited poller, a codex state dir, the real /proc, and one mutation that drops the poll rank and turns the first arm red.
