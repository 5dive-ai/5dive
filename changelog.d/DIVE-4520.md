## Unreleased — fix(task): the auto-mergeable hint names `task merge`, and `task done` refuses to re-deliver a graded merge (DIVE-4520)

The board printed, on every auto-mergeable graded row, an instruction whose verb **destroyed the
standing of the only seat that could have merged it**. Running the hint is what stalled the row.

On a loop row `5dive task done` is not a close: it takes the maker→verifier routing fork and
re-delivers. On a row that is already graded PASS that re-delivery carries no new work, but it still
stamps `handoff_delivered_at=now` — and `_TASKS_TFV_SQL`'s DIVE-4357 conjunct then reads a delivery
clock later than every verdict clock as *a delivery the grade did not grade*. `_task_merge_preflight`
refuses the seat `graded_by` names, which is the one seat the DIVE-3474 rail accepts. Exit 0, no
warning, and a state strictly worse than before the tap. Measured on DIVE-4491 / #963, 2026-09-14, by
a seat doing exactly what the board told it to do.

DIVE-4512 (#966) fixed **which seat** the board names. It did not touch **what the board tells that
seat to run**, so the correctly-named seat was handed the verb that revokes its own standing.

Two halves, and both are needed:

- **`src/task/loops.sh`** — the `merge_hold_reason` cell now reads ``auto-mergeable at the graded sha
  — run `5dive task merge <ident>` ``. That removes the trigger.
- **`src/task/status.sh`** — `task done` on a row that is graded-and-waiting-on-a-merge now **refuses**
  instead of re-delivering, naming the verb that works and the seat that can run it. That makes the
  verb safe no matter what points at it — an older board line, a quoted screenshot, a person. The
  rule was already written on the wiki before this row existed and it did not stop the tap that
  measured it; text-only enforcement is a proven repeat-defect class here (DIVE-4440).

**The guard's predicate is the shared one.** `_TASKS_TFV_SQL` already means "graded PASS, bound to a
pull request, no live reject", and it is exactly what the board renders as `graded->merge:<seat>`.
Re-typing those conjuncts would be a second answer to a question the store already answers, and the
two would drift the first time either moved — DIVE-4357 moved one of them once already.

**Scoped to the close path, not to `_task_route_to_verifier`.** That helper is also `task deliver`'s
funnel, and a maker re-pointing a binding at a new pull request is delivering something the grade
never saw. That is a real delivery and still goes through. The escape from the refusal is the
existing `--force-redeliver="<why>"` (DIVE-4144), which already means "this unchanged re-delivery is
correct"; a second flag for the same sentence would leave the audit unable to say which was meant.

Acceptance is behavioural, in `tests/task_merge_disposition_unit.sh`: C1c/C1d grade the hint's verb
(both halves — a cell offering *both* verbs fails), and C9a–C9p tap `task done` on the DIVE-4491
fixture and ask the **shipped** `_task_merge_standing_sql` whether the graded seat still holds
standing afterwards, with the ACKing seat and a live-reject row as in-population negative controls.
The fixture's verdict clock is pushed 30 minutes back on purpose: at `datetime('now')`'s one-second
resolution an unguarded re-delivery ties rather than overtakes, and the arms could not fail.

Mutants, driven by hand: restoring the `task done` string reds 2 arms; deleting the guard call reds
6; widening the guard past merge-pending reds 2; downgrading the refusal to a warning reds 2.

## Iteration 2 — the already-merged branch, and the second composer

main2's grade bounced iteration 1 on a case the predicate cannot see. `_TASKS_TFV_SQL` reads clocks
and columns, never merge state, so a row whose pull request landed ten minutes ago satisfies every
conjunct and the new guard fires on it — refusing the hand-off with "the verb for this row is
`5dive task merge <ident>`" on a pull request that is already merged. That is not a corner: it is the
branch the fleet's own wake dispatch sends the merge owner to.

**The predicate stays probe-free and the TEXT carries the case.** A GitHub read in the close path is
the one thing DIVE-4137 asks us not to add, and a probe that failed open would make the refusal
non-deterministic. So the refusal now names the already-merged case outright: on a landed pull
request the hand-off IS the unchanged re-delivery `--force-redeliver` exists for (the standing it
would spend is already spent), and there is a second route that stamps no delivery clock at all —
`5dive task assign <ident> <verifier>`, after which that seat's own close finishes the row, which is
the fork the guard is not on.

**The second composer is fixed in the same pass.** `src/cmd_heartbeat.sh`'s graded-merge wake
dispatch is the first text a merge owner reads, ahead of any board cell, and its branch (1) named the
same destructive verb — measured by ops on themselves (DIVE-4485, both pull requests already merged,
the row re-delivered). Branch (1) now hands the row to its verifier with `task assign`, and branch
(2) routes its termination through (1) instead of ending in a bare "then close".

**`--force-redeliver`'s warning is conditional**, because the cost is: on a landed pull request there
is no merge left to hold standing for, and asserting the loss flatly argued against the escape
exactly where the escape is right.

Arms added: C9q–C9s (the refusal addresses the already-merged case, names the escape that applies on
THIS row and its own verifier, and says why), C9t–C9v (the escape is not decoration — `task assign`
onto the verifier moves the row off the guarded fork, stamps no delivery clock, and leaves the
grading seat's standing intact under the shipped predicate), C9n2 (the warning's cost is stated as a
condition), and in `tests/heartbeat_graded_merge_dispatch_unit.sh` arms 5e/5f plus a non-degenerate
arm 9 where verifier and merge owner are different seats.

Mutants, driven by hand: deleting the already-merged clause reds 3; restoring `task done` as branch
(1)'s verb reds 3; naming the woken seat instead of the verifier column reds 2; reverting the warning
to the flat sentence reds 1. The iteration-1 mutants still reproduce (hint string 2; guard call sites
now 11, up from 6, because the new arms also depend on the guard).

## Iteration 3 — the named escape is refused by its own guard, so narrow that guard

quinn's grade bounced iteration 2 on the escape it added. The refusal (and, after iteration 2, the
wake dispatch) names `5dive task assign <ident> <verifier>` — and `cmd_task_assign` **refused it on
exactly the rows the refusal is printed on**. Measured on the suite's own C9 fixture:
`task assign <ident> quinn` returned rc 3, "'quinn' is <ident>'s own verifier — a maker can't grade
itself", and nothing moved; the same verb to a seat that is not the verifier returned rc 0.

The precondition of the advice was the negation of the precondition of the guard that printed it.
`_task_done_merge_pending_guard` is called at two sites and both sit inside a `verifier != assignee`
branch; DIVE-3097's guard fires when `who == verifier AND assignee != verifier`. Every row that could
see the advice was a row the advice could not be run on.

**`src/task/crud.sh` — the guard now reads the column its own comment means.** DIVE-3097 was written
to stop *manufacturing* the maker-is-also-grader shape **fresh**, and its comment says so: "with no
handoff ever recorded (DIVE-2899: assignee=verifier, delivered_at NULL)". It tested
`assignee != verifier`, which is a proxy for that and holds only while a row has never been
delivered. A delivered row that was bounced, re-assigned or graded also sits at
`assignee != verifier` — with a handoff clock stamped. The conjunct
`handoff_delivered_at IS NULL` is what "no handoff ever recorded" actually is, and it is now what
the guard tests. A row that HAS a handoff clock cannot be the fresh shape DIVE-2899 named.

That one clause clears quinn's (2) as well: the wake dispatch's branch (1) already names this verb,
and now that verb runs on that shape. No dispatch text changed this iteration.

**The escape is graded by RUNNING it, not by grepping the refusal.** quinn's (3): iteration 2's
C9t–C9v wrote the end state by hand (`UPDATE tasks SET assignee='quinn'`) and asserted the
consequences, so `grep -c cmd_task_assign` over both harnesses returned 0 — the arms certified what
the refusal *says* and never ran the verb it names, which is the DIVE-4440 text-only-enforcement
class this row was filed to end. C9t–C9w now call the shipped `cmd_task_assign` (only
`_task_require_lane` is stubbed: it reads the agent registry, this board is a temp fixture, and lane
registration is not what is under test) and assert rc 0, the row moved off the guarded fork, the
delivery clock UNCHANGED, and the grading seat still holding standing under the shipped
`_task_merge_standing_sql`. C9x is the in-population positive control — the same verb to a
non-verifier seat — so a C9t that went green because the verb became a no-op is distinguishable from
one that went green because the guard stopped firing.

**C9y/C9z are the control the narrowing must not eat**: a never-delivered row
(`handoff_delivered_at NULL`) reassigned straight onto its own verifier is still refused, by
DIVE-3097's own sentence. That is the shape DIVE-2899 named and it is untouched.

`tests/task_merge_disposition_unit.sh` 139 pass / 0 fail. Mutants, hand-driven with the anchor count
verified at 0 before the suite was re-run: re-arming DIVE-3097's guard (drop the narrowing conjunct)
reds C9t and C9u; deleting the guard outright reds C9y and C9z.
