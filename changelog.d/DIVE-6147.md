## Unreleased — fix(task): grade-context diffs against the pull request's base, not the checkout's stale origin/main (DIVE-6147)

`5dive task grade-context` took the packet's diff base from `merge-base <sha> origin/main`
in the delivery checkout, whose `origin/main` nothing fetches. On one measured packet that
ref sat 64 commits behind the pull request's base, so the diff spanned 221 files while the
PR changed 3, and the 128 KB cap cut two of the three out. The grader is told to judge only
the packet, so it was shown commits the maker never wrote and not the code they did.

When the pull request was read, the base is now the merge-base of the served sha and the
PR's `baseRefOid` — the same diff `gh pr diff` shows. A base the checkout does not hold is
fetched as objects only, so no ref in another seat's checkout moves. An unbound or
unreadable row keeps the local merge-base. The packet's new `BASE_SOURCE:` line says which
was used, and a fallback taken because the PR's base could not be fetched says the diff may
carry commits the maker did not write.

`tests/task_grade_context_pr_base_unit.sh` builds a checkout whose `origin/main` is behind
the PR's base, with upstream files large enough that the wrong base pushes the maker's file
past the cap. 11 arms pass; 6 of them fail on the pre-fix tree.
