## Unreleased — feat(agent): a new seat's tier follows its role: team leads and agents with no team lead are admin, team members standard (DIVE-7143)

A new seat used to be admin only if it was the first on the box (DIVE-1002), or if a partner box set every seat to admin (DIVE-6410). The box's `seat-isolation` rule is now `by-role` by default, on every box:

- An agent created or imported on its own has no team lead, so it is admin. A pack's manifest can narrow a lone import to standard or sandboxed, so an exported standard seat comes back standard. It can never widen one.
- `team import` / `up` sets each seat by where it sits. The lead (the seat with no `reports_to`) is admin and a member is standard, on both the create and the pack-import path, so a pack's manifest never decides a seat in a team. A seat's own tier in the template is now forwarded on the pack path too. 5dive-api writes one per seat, and adds admin for Leadership, Engineering and Ops members.
- A member's Reporting block now sends root work to its lead, and the box-wide CLAUDE.md says the same for every standard seat.

`5dive config seat-isolation=by-role|admin|standard|default`: `admin` keeps every new seat admin, and `standard` restores the old first-seat-only rule. **No existing seat changes.** The rule is read when a seat is created, and `agent grant <name> admin` remains the way to widen one.
