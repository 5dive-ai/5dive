## Unreleased — fix(task): a run counts a human touch when a human answered its gate, not when a gate was filed (#1016)

`runs.human_touch` was set at gate-FILING time for every tier above 0, and tier
says how big an ask is, not who answers it. A tier-1 gate is routed to the lead
seat — an agent by construction, queued with no a2a send and no wake — and
cleared by that agent, so every lead-reviewed row reported a person who never saw
it. Measured on a live box, one `trace` invocation printed the attempts line
`[human touch]` beside the verdict `zero-human — 0 human touchpoints`: two
metrics for one question, disagreeing, and that question is the one the
zero-human thesis is graded on.

The flag now follows the predicate `trace` already used — `need_answered_by LIKE
'human:%'` — at the two moments the answerer is actually known. At ANSWER time it
keys on the provenance that landed on the row, so `auto:ttl`, `auto:reject` and
`auto:t0` charge nobody at any tier. At WITHDRAW time it keys on delivery:
`gate_pinged_at` set with no answer means the ask reached someone's chat, which
preserves the "filed and withdrawn still cost a human" property the original
comment defended — and that read must happen before the withdraw transaction,
which nulls the column itself.

`tests/run_human_touch_at_answer_unit.sh` grades the matrix against a sandbox
store with a mutant arm restoring the filing-time charge, and
`tests/runs_unit.sh` section 7 moves from the old tier rule to the new one.
