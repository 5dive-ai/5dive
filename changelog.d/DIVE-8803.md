## Unreleased — fix(task): a gate goes to the owner's DM, not to a group the agent sits in (DIVE-8803)

An owner added their agent to a Telegram group with other people. The agent's question for its owner («🙋 [DIVE-7] needs you», with its buttons) was posted to that group, where everyone read it, instead of the owner's DM.

The telegram plugin moves `last-human-chat.json` on every human message it accepts, in a DM or an allowed group, from any member of the group. `_task_send_owner` took a group pointer at its word, so the last word from anyone in the group decided where the owner's gate went.

Now a group named by the pointer takes an owner send only when it is the owner's room: `access.json` binds it to a topic (`agent config telegram.home-channel`, a forum seat), or the bot has no owner DM at all. Otherwise the pointer is ignored and the send goes to the owner's DM, with the groups as the fallback when the DM fails, as before. The pointer file is not changed. The filer's preview (`_task_legacy_owner_destinations`) follows the same rule. A DM pointer, a bound topic, a group-only bot and a box with named humans behave as before.

Button taps on a gate were already owner-only in the plugin; typed replies to a gate in a group are fixed there separately.

`tests/gate_group_pointer_owner_dm_unit.sh` (11 arms) stubs only the Bot API send; 4 arms are red on the unpatched tree.
