## Unreleased — fix(task): a follow-up on a finished task files a linked child task instead of refusing (DIVE-6157)

`5dive task followup <ident> --text=…` on a done or cancelled row used to refuse with
"<ident> is done — nothing to follow up. File a new task instead." The owner's common case
after a task finishes ("now do the same for X", "that's wrong, fix it") had no path from the
task itself, and the Mini App could not offer a Follow up box on a finished task.

A finished row is still not reopened: done is terminal, and reopening would scramble its
verifier, landing and result history. Instead the follow-up files a NEW row with
`--parent=<ident>`, the same assignee and priority, title "Follow-up: <first ~60 chars>", and
a body holding the text, "Follows <ident>: <title>" and that row's result. The assignee is
woken once, naming the child, and the JSON reply adds `child`, `child_id` and `child_title`.
The open-row path is unchanged byte for byte.

`tests/task_followup_unit.sh` adds the F arms: exactly one child, parent set, same assignee,
text in the body, exit 0. They are red against the pre-fix source.
