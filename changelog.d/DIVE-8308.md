## Unreleased — fix(agent-start): Claude seats on your own AI provider know their model's real context window (DIVE-8308)

A Claude seat on Qwen, OpenRouter, DeepSeek, Kimi or GLM now launches with its model's real context
window (`CLAUDE_CODE_MAX_CONTEXT_TOKENS`). **Existing seats pick it up on their next restart.**

Claude Code does not know these models, so it assumed a 200k window: a 1M model compacted at a fifth
of its room. Our 400k compaction default (DIVE-7892) also hid Claude Code's own warning about it. A
customer box had to set the window by hand on two seats (983,616 for `qwen4-max-preview`, 1,000,000
for `deepseek-v4.1-flash` through OpenRouter).

Where the window comes from:

- **OpenRouter:** its public model list (no key is sent), cached for a day in the seat's home. A
  failed fetch uses the last copy. Never fetched in local-only mode.
- **DeepSeek, Kimi, GLM, Qwen Token Plan:** a small table of the catalog's own model ids.

One value covers every model the seat calls, so the smallest window among them is used. The seat
still compacts at 400k, or sooner when the model's window is smaller: a 131k model compacts at 131k.

Nothing is exported when a window is unknown (an unlisted model, your own endpoint): the start
script logs a warning naming the model instead of guessing. Your own value always wins: one in the
seat's environment, or `env.CLAUDE_CODE_MAX_CONTEXT_TOKENS` in its user, project or managed settings.

`tests/claude_byo_context_window_unit.sh` runs the start script's own type case: 35 arms, 16 of them
red on the script before this change.
