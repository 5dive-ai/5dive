## Unreleased — feat(agent): a new hire's first job is a done task on the box, its result the agent's reply (DIVE-5946)

When `agent _first_job_run` gets the agent's reply it also files the job as an
ordinary task: assigned to the agent, created by `telegram` (the owner in the app),
status `done`, title the job, result the reply. The Mini App's and my2's Tasks screen
show it like any other task's result, so an owner who never made the agent's bot still
sees what the agent did. The task is written born done, in one insert, so the heartbeat
never dispatches it and the agent never does the job twice; its ident is kept on the
first-job record, so a restarted run files no second one. The done report
(`POST /server/first-jobs/done`) names it as `task`, and the API's notice opens it in
the app. The reply still goes to the agent's Telegram plugin as before. A board that
refuses the insert costs only the task, never the job or its report.

`tests/agent_first_job_unit.sh` T1-T4 pin the row, the restart, the failed ask and the
refused insert; NC2 is the negative control for the restart check.
