### Fixed

- **`_spend_scan_task_ids`: an unreadable project SUBDIR is NOT-REACHED, not a partial total
  (DIVE-3417).** DIVE-3345 put a guard on `projects/` and a guard on each `*.jsonl`. The pattern is
  `projects/*/*.jsonl` — there is a THIRD directory read between them, the middle `*`, and
  `glob.glob()` performs it by swallowing every `OSError` and yielding nothing for that entry. A
  project subdir this uid could not read therefore dropped out of the sum with no exception, no
  stderr and rc 0: a well-formed number that is a FRACTION of the truth.

  That is not the milder blind-guard shape. It is the CLOBBER shape DIVE-3345 exists to kill —
  `_loop_refresh_spend` accepts rc 0 + numeric as a successful read and PERSISTS it over the
  accumulated `tokens_spent`, so one unreadable subdir permanently halves a durable figure and the
  throttled fast path then reads that back. Measured by ops on `fac4aea`, uid 1016, on a two-subdir
  fixture worth 60000: `rc=0 out='30000'`.

  Reachability is HIGHER on a normalised host, not lower. `/etc/cron.d/5dive-agent-home-traversal`
  (the DIVE-3294 stopgap, every 20m, root) makes the UPPER path traversable — which manufactures
  exactly the readable-`projects/`-over-unreadable-subdir state rather than preventing it.

  The middle level is now enumerated explicitly by a new `list_sessions()` (`os.listdir` per level,
  which is allowed to RAISE) instead of by `glob`, which cannot report what it skipped. `glob` is no
  longer imported by this scanner.

  Two skips are kept deliberately, because both mean "nothing unread here" rather than "we failed to
  read it", and both match what the glob did: `ENOENT` (the entry vanished mid-scan — sessions and
  their dirs roll over under a live agent) and `ENOTDIR` (a regular file sitting directly in
  `projects/`, which cannot contain `<it>/*.jsonl`). `ENOENT` on `projects/` ITSELF is also a skip:
  `probe_readable` has just classified that as a genuinely idle agent, and NOT-REACHING it would
  over-fire on every agent that has never run — which disables the ceiling as thoroughly as the
  fail-open does. That arm was caught red by DIVE-3345's own STATE-3 assertions during this change,
  not reasoned about afterwards.

  One deliberate WIDENING over `glob.glob`: glob hides dot-prefixed names at both levels. A
  dot-prefixed session file is still spend, and silently not counting it is the shape being refused.

### Testing

`tests/spend_scan_not_reached_unit.sh` gains the row's own fixture — one home, two project subdirs,
30000 in-window tokens each — and grades the middle level the way DIVE-3345 grades the levels around
it: every sick arm PAIRED with the same fixture healed, and asserting not merely "non-zero rc" but
that the well-formed HALF is never returned.

- **`EACCES`**, the production shape and the row's fixture: `chmod 000` on one subdir under a
  readable `projects/`. Unprivileged only — root lists a 000 dir regardless — so it is skipped rather
  than faked.
- **`ELOOP` (ANY-UID)**: a self-referential symlink where a project dir belongs. `os.listdir` raises
  for root too, so a uid-0 runner still exercises the defect. This is the middle-level analogue of
  the `ENOTDIR` arm fac4aea added one level up, for quinn's reason: *"a green that skipped the point
  is not a grade."*
- **Over-fire controls**: a dangling symlink and a stray FILE in `projects/` must stay SKIPPED, not
  NOT-REACHED — a live agent rolling a session over must not wedge the scan.

Non-vacuity, same harness both sides, uid 1015, unprivileged: **28/6 on the pre-fix tree (fac4aea),
34/0 after.** Every red is `rc=0 out='30000'` against an expected 60000 — ops's measurement
reproduced, including on the ANY-UID arm.

### Audit (acceptance 4): every wildcard on a spend/usage path

Three `glob.glob` call sites read transcripts. All three use the same two-wildcard
`projects/*/*.jsonl` shape.

| site | `projects/` | middle `*` (project dir) | `*.jsonl` |
|---|---|---|---|
| `cmd_loop.sh` `_spend_scan_task_ids` | guarded (`probe_readable`, rc 2) | **fixed here** (rc 2) | guarded (per-file `OSError`, rc 2) |
| `cmd_usage.sh:184` `usage_collect` | guarded (`probe_readable` → `coverage.unreadable`) | **UNGUARDED — silent partial** | guarded (`denied` → `coverage.unreadable`) |
| `cmd_usage.sh:1073` `activity_collect` | **unguarded** | **unguarded** | **unguarded** (bare `except OSError: continue`) |

`usage_collect` has the identical top-and-bottom-but-not-middle shape: an unreadable project subdir
leaves the agent in the READABLE set with a short total and `coverage.complete` still true, so the
"⚠ NOT checked" surfaces built on that flag stay quiet. Milder than the loop scanner — it is a
report, not a guard that persists over durable state — but it is the same defect.

`activity_collect` has no readability contract at ANY level, and still resolves `home` through the
guessed `/home/agent-<name>` fallback DIVE-3345 removed from the loop scanner. Giving it a
NOT-REACHED contract is a design change, not a patch.

Both are left to **DIVE-3419**, filed with this measurement, rather than widened into this row: the
acceptance asked which wildcards are guarded, and a second producer's contract should be graded by
its own harness (`usage_coverage_unit.sh`), not smuggled in under this one.

Out of scope, named so nobody re-derives it: the shell globs in `cmd_memory.sh` / `cmd_doctor.sh`
(`~/.claude/projects/*/memory`) have the same unguarded middle wildcard, but they fail LOUD ("no
memory stores found") instead of producing a number, so a skipped level cannot be mistaken for a
measurement.
