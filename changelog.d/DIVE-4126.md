## Unreleased — fix(plugin): the bundled browser plugin can actually be installed, and every bundled plugin is now graded on installing (DIVE-4126)

v0.28.0 shipped the browser plugin and **no customer could install it**. `sudo 5dive plugin add
browser` refused with `unknown grant 'browser-profiles'`: the manifest declared a grant the
enforcer's enum did not carry. Measured on lodar's box (`5dive-exact-swallow`, Ubuntu 24.04,
installed v0.28.0, 2026-09-09 03:40Z) — and `5dive browser --help` was rc 2, an unknown command,
on every box for the same reason.

**`browser-profiles` is now a contract §1 grant, with the two halves that make one real.** The
consent screen renders it in English ("the browser profile store — the logged-in sessions you
authenticated by hand"), and the installer enforces what it authorises: exactly
`$STATE_DIR/browser-profiles` (root, `0711`) with per-seat `0700` subdirectories, and nothing
under `fs-home`. A profile directory IS a credential, so the grant names one root outside every
home rather than handing the plugin a home to rummage.

**Creation stays a root act.** `plugin add` does not provision the seat directory; it prints
`fivedive.setup` and the human runs `sudo 5dive browser setup`, the shape voice already uses. On
a parent any seat can write to, a hostile seat pre-creates another seat's directory name, owns
it, and every session that seat later authenticates lands somewhere it can read. What the
installer does enforce is fail-closed: an **absent** store is the fresh-box path and installs
fine, while a store that **exists** and is not a root-owned `0711` directory refuses the install
rather than layering a plugin on top of a store that hands sessions to the wrong uid.

**Why no test caught it, which is the durable half.** `tests/plugin_contract_unit.sh` builds
fixture plugins to grade one rule each, so the only manifests it validates are ones it wrote
itself; the bundled arms set-compare the staged FILE list, which grades that a directory arrived
and never that it installs. Nobody asked the customer's question. `tests/plugin_bundled_install_unit.sh`
asks it of **every** directory under `plugins/`, discovered at run time so plugin number three is
covered the day it lands: install exits 0, the registry records it enabled, and the verb it
declares dispatches. Negative controls keep the green honest — an unknown grant is still refused,
every grant in the enum must render in English, and the profile-store enforcement is graded on the
owner/mode pairs an unprivileged harness cannot create on disk.
