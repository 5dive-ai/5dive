## Unreleased — fix(bug): a self-installed box sends its bug report, and the error says why it could not (DIVE-6616)

`5dive bug --file` sent only with the box key in `/etc/5dive/connectord.env`,
and only boxes on our control plane have that file. On a curl-install box every
owner-approved report was spooled and never sent, and the error said "this seat
cannot read the box's key", which reads as a permissions problem that was not
there, even for root.

Now, when that file does not exist, the same allowlisted payload goes to the
API's open `POST /bug-reports` route with no key (the API caps it per sender IP
and across all such boxes). The owner's yes and the one-ask ledger are
unchanged. The spool drains over the same route, so reports saved earlier go
out on the next approved send. A key file that exists but this seat cannot read
still gets the access message; one that holds no key says so; a readable key
uses the keyed route as before. If the open route cannot be reached (an API
older than this CLI), the report is spooled and the error names the
self-installed case.

`tests/bug_report_file_to_api_unit.sh` arm 5 covers each case against a mock
endpoint: 64 arms green; the key-absent arms (16) are red on the pre-fix tree.
