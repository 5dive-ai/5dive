## Unreleased — feat(agent): `agent first-job` runs the owner's first job at hire and leaves the reply for the agent's bot (DIVE-5874)

After a hire in the Mini App the owner can pick a small first job. The API execs
`5dive agent first-job <name> --token=<t> --job-b64=<b64>` on the box (root, over the
existing box channel). The verb records the job under `/var/lib/5dive/first-jobs/` and
returns at once; a transient unit (`5dive-first-job-<token prefix>`) asks the agent
through `agent ask` with a static prompt, writes the reply to the agent's
`.claude/channels/telegram/first-reply.json` (as the agent, 0600) for the Telegram
plugin to send on the owner's `/start`, and reports `POST /server/first-jobs/done` with
the box token on curl's stdin. A repeat call on the same token starts nothing.
`agent first-job status <name> --json` reads back the plugin's `startAt`/`secondAt`
stamps. The job runs on the agent's own AI on the customer's box; nothing on 5dive's
side generates text.

`tests/agent_first_job_unit.sh` pins argument validation, the token shape, idempotency,
the unit argv, the prompt, the reply file and the done POST body, with a negative control.
