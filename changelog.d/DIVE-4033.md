## Unreleased — fix(self-update): the restart sweep no longer resurrects an operator-parked agent (DIVE-4033)

`desiredState: stopped` is the operator's recorded intent — `5dive agent stop` writes it, and the
supervisor, the heartbeat, `agent send --wake` and the objective preflight all read it. **The
self-update restart sweep was the one path in the tree that never asked.** `git grep -l desiredState
-- src scripts` returned six files and `src/cmd_selfupdate.sh` was not among them.

Measured on a 37-agent customer box on 0.26.0: `katya` carries `desiredState: stopped` and the
03:07 update window restarted it anyway (`Stopping … Stopped … Started`, then
`5dive-agent-start: agent=katya`). The CLI then printed both halves of the contradiction itself —
`agent list` said `active  disabled`, `agent info` said `state: active / disabled`. That is not a
state an operator can act on, and it had been burning a `claude-fresh` seat on a 720-minute
heartbeat while marked parked.

**The cost is not the seat.** On that box `katya` is a customer-facing sales bot for a project
closed on 2026-08-19. It was parked deliberately and came back on its own, which is a consent
problem rather than waste — hence high rather than the reporter's medium.

- **Both restart paths now consult the registry**: the nightly `cmd_self_update` loop and
  `_pending_restart_sweep` (the deferred-bounce pass DIVE-3173 added, which the heartbeat tick also
  drives). A parked agent is reported in a new additive `parked` / `parked_count` pair on the
  self-update JSON and in the heartbeat's pass-done line, so it is machine-readable and not only
  prose. Every existing field keeps its exact prior meaning.
- **It skips; it does not enforce.** The honest remedy for a running-but-parked unit is to stop it,
  and self-update is not the place: stopping mid-turn is destructive, and reconciling the registry
  against systemd is the supervisor's job. So this path declines to perpetuate the contradiction by
  its own action and says the contradiction out loud, naming **both** exits — `5dive agent stop
  <name>` if the stop is real, `5dive agent start <name>` if the intent is stale. Only a person
  knows which, and a bare "skipped" would read as a decision already taken.
- **Absent is not stopped, and unreadable is not stopped** (DIVE-2318, and the `// "running"`
  default every other reader already uses). An agent never start/stop'd through the CLI carries no
  field at all — the common case — so it restarts byte for byte as today, as does an agent missing
  from the registry, a missing registry file, absent `jq`, and a truncated JSON body. The two
  failures are not symmetric: a wrong skip freezes the fleet silently on the old payload (DIVE-3173's
  NEVER FIRES; DIVE-1095 is a whole row about a fix that shipped dormant), while a wrong restart is
  loud and recoverable.
- **The marker is cleared, not held.** A parked agent's owed bounce is dropped rather than deferred
  forever: holding it would report a debt payable only by resurrecting the agent, and it is not owed
  either way — whichever exit the operator takes, the unit ends up stopped or restarted, and both
  load the new payload by construction.
- **In the sweep the question is asked after the is-active guard**, not before it. A parked agent
  whose unit is already down is the state the operator asked for, and shouting about it every sweep
  would bury the case that is genuinely wrong. In the self-update loop it is asked *before* the
  payload predicate, so a parked agent is never reported as `skipped (payload unchanged)` — true on
  a CLI-only night, and silently replaced by a resurrection on the next night the payload moves.

`tests/self_update_parked_agent_unit.sh` runs the shipped bytes extracted from the fence markers —
20 arms, including the end-to-end `cmd_self_update` path with the two-unit registry from the report
(`katya` parked, `nova` running: one is left alone, the other still bounces). Every positive arm is
paired with a negative control that only passes because the skip does *not* fire on an unknown, so
the FREEZES direction cannot pass by accident. Six mutants — deleting either guard, reading an
unreadable registry as parked, defaulting an absent field to stopped, loosening the exact-value
comparison, and moving the check behind the payload predicate — are each killed by 1–3 arms.

**Not claimed.** The report also lists `fobos`, `mars` and `lunaparser` as parked agents that all
entered active in the same 03:07 window, suggesting the sweep cold-starts stopped units too. That
is unverifiable — journald on that box retains ~90 minutes and the 08-04 records are gone — and the
enumeration is `systemctl list-units --state=running`, which cannot reach a stopped unit. Only the
`katya` restart is proven. The fix covers both shapes regardless, because it keys on the registry
rather than on how the unit was reached.

**Left open.** `active / disabled` is still representable — this change stops one writer of that
state without making the pair self-describing in `agent list` / `agent info`. That is a separate
surface and wants its own row.
