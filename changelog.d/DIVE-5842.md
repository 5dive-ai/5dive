## Unreleased — feat(host): an admin seat searches the whole journal, with every secret masked (DIVE-5842)

Since DIVE-5805 no seat is in `systemd-journal`, and the only log verb an admin seat had,
`sudo 5dive host journal --unit=<unit>`, read one unit at a time and printed it raw. So a
seat could not retest "did any key land on a sudo line since the update?", and a read of
the right unit still printed an old leaked line in clear.

- `5dive host journal` takes `--comm=<process>` (e.g. `sudo`) and `--grep=<text>` as well
  as `--unit`. `--grep` is a fixed string, matched after masking, so it cannot be used to
  guess a key one character at a time. A search reads the `--since` window (one day when
  none is given), then keeps the last `--lines`.
- Every line it prints is masked, unit mode included: `sk-ant-…`, `sk-or-…`, `ghp_…` (and
  `gho_`/`ghu_`/`ghs_`/`ghr_`), `github_pat_…`, Telegram bot tokens, `Bearer …`, and the
  value of any `NAME=` whose name contains TOKEN, KEY, SECRET or PASSWORD.
- `--count-secrets` prints only how many lines held a secret, so a retest never prints a
  value: `sudo 5dive host journal --comm=sudo --since=2d --count-secrets`.
