## Unreleased — fix(push): the pre-push rail's audited override now reaches a delegated push (DIVE-4288)

- `scripts/pre-push-rail.sh` refuses a red push and advertises an audited escape,
  `FIVE_PUSH_OVERRIDE="$(cat reason.txt)" git push`. That escape was unreachable from every
  delegated-push seat: `5dive push` hands the push to root over a plain `sudo -n`, which strips
  the variable, so the rail saw an empty reason and printed NEITHER of its two outcomes — no
  OVERRIDDEN block and no clause refusal. Measured 2026-09-11 on DIVE-4282: a five-clause reason
  exported in front of `5dive push` simply vanished and the push was refused.
- The reason now rides the SAME stdin channel as the push parameters, as an optional fifth field
  (the whole remainder of the stream, because a signed reason is multi-line by construction).
  Deliberately not a sudoers `env_keep`, which would widen the grant for every command on the box
  to fix one call.
- The five-clause grading moved ROOT-side and runs before anything is spent: an agent cannot fake
  the audit line, and a reason missing a clause is refused by number. The rail keeps its own copy
  of the predicate for ordinary `git push`; `tests/push_override_delegated_unit.sh` runs both over
  one fixture corpus and requires them to agree.
- When a push is delegated, the rail and the pre-push hook now advertise
  `FIVE_PUSH_OVERRIDE=... 5dive push <row>` instead of `git push` and `--no-verify` — neither of
  which a credential-less seat can run. Printing a dead end is what sent DIVE-4282 to "hand the
  branch to a credentialed seat, or edit the red gate".
- An accepted override prints the path of the log it was written to, and WHO IS WRITING DECIDES
  WHERE: when the rail runs as root (a delegated push), the receipt goes to the root-owned
  `/var/log/5dive/push-override.log`, not to `<git-common-dir>/5dive-push-override.log` inside the
  agent's own checkout. Carrying the reason across the boundary is what made that append reachable
  root-side for the first time, and `>>` writes THROUGH a symlink — so the earlier shape would have
  let an agent plant the log path as a link and have root append its text to, and chown, any file
  root can write. The crossing is deleted rather than guarded: root writes nowhere the agent
  controls, `_push_do` performs no `chown`, and printing the path is the whole of what "findable
  from the seat that signed it" asked for (the file is 0640 root:claude, readable by every seat).
  Found by main2 grading iteration 1 of this row; see
  `community/wiki/a-fix-that-makes-a-path-root-reachable-inherits-that-paths-safety.md`.
