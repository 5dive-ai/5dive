## Unreleased — fix(plugin): a bare `plugin add browser` installs the current 5dive-browser release, not the registry's old mirror (DIVE-6241)

On a fresh box, `5dive plugin add browser` installed `browser@5dive-plugins` 1.32.0. That is the
registry's copy of the browser plugin, synced by hand, and it had fallen seven releases behind
5dive-browser (1.39.0). Round 2 of the Claude in Chrome head-to-head hit it on 2026-10-14 and had
to install with `plugin add 5dive-ai/5dive-browser` instead.

A bare `plugin add browser` now installs from 5dive-ai/5dive-browser, and says so. The list is
`FIVEDIVE_BARE_ADD_REPO` in `src/header.sh`. The qualified `browser@5dive-plugins` still installs
the registry copy, and a box that already runs it keeps it, because two copies would claim the same
`browser` verb. The app's catalogue is unchanged.

`tests/plugin_bare_add_repo_unit.sh` covers it with seven checks: the bare name, the qualified name,
another plugin (voice), and a box already on the mirror. A mutant that empties the list fails it, and
three of the checks fail on the tree before this change.
