## Unreleased — fix(agent): a new seat on a box with one Claude login comes up signed in on it (DIVE-7028)

On a self-hosted box with one Claude login, every new seat came up signed out and
someone had to run `agent config <a> set auth-profile=<login>` by hand:

- `agent import --auth-profile=mp` always added `--defer-auth`, so the named,
  signed-in account was bound but reported "auth was deferred (agent is UNAUTHED)".
- `hire <role> --from-market` (and any import with no account) minted a new, empty
  profile named after the hire.
- `team import --auth-profile=<p>` with a `defer_auth: true` template left every seat
  unauthed.

Now `agent create` (and so hire, import and team import, which all run it):

- uses an account named with `--auth-profile` that is already signed in, and never
  defers it;
- with no account named, uses the box's ONE signed-in Claude account. A second
  account, the shared login, a BYO key or a codex seat keep today's behaviour, and
  the free demo AI never counts as that account;
- on a box linked to 5dive.app chat (`/etc/5dive/chat-only`), gives a claude/codex
  seat with no `--channels` the app chat at create, instead of a minute later from
  the box's reporter.

`tests/create_sole_account_default_unit.sh` drives the real `cmd_create` (stopped
where the agent user would be made) and the real `cmd_import` seam on fixture boxes:
28 arms, 17 of them red on the pre-fix tree.
