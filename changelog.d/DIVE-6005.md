## Unreleased — fix(agent): Enable chat rolls channels back when the box install fails, and no longer races a fresh seat's marketplace clone (DIVE-6005)

Enabling chat right after a hire could fail on the box yet still leave the agent recorded
chat-enabled: the channel installer exited after the registry already listed the new channel,
and the dashboard reads only the registry, so it showed a chat that never answers. Every
channel install in `agent config` now runs through one wrapper that, on failure, rolls the
registry and `agents.d` channels back, fires no restart, and returns one error envelope, so
Enable chat stays on offer.

The usual cause was a race: a just-hired seat's first session clones the plugin marketplace
into the same directory the installer was wiping and re-cloning. The installer now clones
into a private sibling and renames it into place, waits on a clone already in flight, and
retries a bounded number of times, plus once on marketplace update.

`tests/enable_chat_install_rollback_unit.sh` R1-R9 (rollback) and C0-C5 (concurrent
marketplace fetches); the pre-fix tree is red on 11 of them.
