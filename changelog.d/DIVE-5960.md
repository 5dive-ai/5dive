## Unreleased — fix(heartbeat): reap an off-roster seat's stray shell before its owed restart, and read the poller sweep's clock per seat (DIVE-5960)

Two update-night restart defects in `5dive heartbeat tick`.

**An owed restart never fired for a seat outside the heartbeat roster.** Claude Code reports a
session busy while any background shell it started is alive. The stray-shell reaper (DIVE-4298)
ran only for seats with a heartbeat schedule, so a seat without one and one forgotten shell read
busy to the pending-restart pass forever, and the "restart owed … STILL not idle" line repeated
every tick. The pass now asks the same reaper about each seat that owes a restart, before it reads
the seat's busy state. The reaper's own rules still decide what dies: the pane must read done with
shells still running for two ticks, and a shell under `FIVEDIVE_KEEP_ALIVE` or younger than the
grace age is left alone. A mid-turn seat is never reaped or bounced. A seat swept by that pass is
not swept again by the per-seat loop in the same tick, and a seat with no heartbeat block keeps its
tick count outside one, so it does not start showing up in `heartbeat ls`.

**The Telegram poller check paged a seat restarted while the check was running.** It read the
clock once before looping over every seat, so a unit restarted a few seconds into the loop looked
started "in the future", got no restart grace, and its deleted beacon read as "poller never
started". The clock is now read per seat, after the unit's start time. A start time that is really
in the future (clock skew) still gets no grace and still alarms.

`tests/update_night_restart_unit.sh` drives both sweeps with a stubbed pane, process table,
systemd and clock (17 arms, including both negative controls per fix and a mutant per fix that
goes red on the pre-fix code).
