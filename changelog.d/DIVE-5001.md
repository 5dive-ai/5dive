## Unreleased — feat(owner-ask): a browser ask is answered by one Telegram tap (DIVE-5001)

Browser 1.15.0 stops before a send, post, pay or delete the owner has not allowed, writes
the ask, and then runs `5dive owner-ask browser <request-file>` if the CLI has that verb.
Until now it did not, so every ask waited for someone to type `sudo 5dive browser approve`
on the box.

`5dive owner-ask browser <request-file>` hands the ask to root over one new exact-path grant,
`_owner_ask` (params on stdin, seat from `SUDO_UID`, rendered for standard seats beside
`_task_channel`). Root reads the request as the seat, mints a nonce, and replaces the request
with a root-owned copy that carries `nonce_hash` (a temp file in the same directory, then a
rename). The seat's file is never written in place, and the browser trusts the hash only in a
file root owns. Root then sends the seat's owner, on the seat's own bot, the payload line
exactly as the ask printed it, plus the screenshot (only when it is a PNG, read as the seat),
with Approve and Decline buttons. Their callback data is `bap:<ref>:<nonce>` /
`bdn:<ref>:<nonce>`, where ref is the ask id's 12 hex digits.

The owner is one Telegram id. With a human registry it is the seat's linked human, who must
already be paired to that bot. Without one, it is the bot's single paired DM. Two paired
people and no named owner is refused, not broadcast.

`echo <callback data> | 5dive owner-ask tap --from=<tapper id>` is what the seat's Telegram
plugin runs on a tap. The nonce is read from stdin so it never appears in argv. Root refuses
the tap unless all of these hold: the ask is the calling seat's own, its file is root-owned
(otherwise "never delivered to the owner"), the nonce matches the hash, the tapper is the
owner it was sent to and still owns the seat, the ask is under a day old, and the nonce has
not been spent (spent nonces are recorded with an atomic mkdir). Only then does it run
`5dive browser approve <id> --human-proof=<nonce>` (or `--deny`).

`tests/owner_ask_browser_unit.sh` covers 66 arms, including three mutants that each remove
one guard (the spent record, the owner binding, the rename) and turn that guard's arm red.
