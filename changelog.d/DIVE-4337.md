## Unreleased — fix(task): the merge queue is a state the pull request does not report, so the board now reads it (DIVE-4337)

- **Three world states, one label — until now.** On a queue-protected branch an
  OPEN pull request is QUEUED, was EJECTED unmerged, or was never pressed, and
  after an eviction GitHub renders all three identically: `state=OPEN
  merged=false mergeStateStatus=CLEAN mergeable=MERGEABLE isInMergeQueue=false`.
  The board painted `graded->merge:<seat>` for all three and the DIVE-1830 close
  gate returned the same `state=OPEN, measured` for all three, so neither told a
  merge owner whether to wait, to press, or to re-enqueue something the queue had
  already thrown out. Measured 2026-09-11: #897 (DIVE-4327) left the queue
  unmerged at 19:00:56Z on a **10-second** budget overage after 45 minutes at
  position 1, and #894 (DIVE-4324) the same cycle on a **one-second** overage —
  both graded PASS, both green on their own heads.
- **`_gate_pr_queue_state`, and it has to be GraphQL.** `gh pr view --json`
  exposes neither `mergeQueueEntry` nor `isInMergeQueue`, which is why every
  previous reader reached for `mergeStateStatus` — a column that reads CLEAN for
  a queued PR and carries no queue membership at all. One GraphQL read now yields
  `QUEUED|<position>|<state>`, `EJECTED|<when>|<reason>`, `ENQUEUED|<when>`
  (the add-before-entry window), `NEVER`, or `UNKNOWN|<why>`.
- **The eviction's witness is the timeline, not the workflow run.** The
  merge-group run on `gh-readonly-queue/main/pr-NNN-<sha>` is deleted as the
  queue re-forms groups — #897's failing run was already gone from `gh run list
  --event merge_group --limit 40` twenty minutes later. `RemovedFromMergeQueueEvent`
  is on the pull request and persists, so that is what is read.
- **Two surfaces.** The `done-before-pr-merged` refusal now names which of the
  three states the row is in, and `5dive task show` prints a live `merge_queue =`
  line beside `merge_owner` — fenced to rows that are actually painting
  `graded->merge` (merge_owner set, not done, a pull-request delivery_ref) and
  switchable off with `FIVE_TASK_SHOW_QUEUE=0`.
- **An unreadable queue is NOT MEASURED, never "never enqueued".** Every failure
  mode — no `gh`, a failed read, an error envelope, an unresolvable slug or PR
  number — classifies as `UNKNOWN` and renders as a sentence that says so
  (DIVE-2318's rule: an unreached question must not print as a measured no).
- **Graded in `tests/task_merge_disposition_unit.sh` (section G, 20 arms, +0.5s
  measured on the control plane), not in a new file.** The core tier was 310s
  against a 300s cap in the cycle that produced this row; a new harness there
  would have added weight to the tier that was ejecting the graded passes. Four
  mutants of the shipped functions were killed by hand — the field-count guard
  degrading to `NEVER` (3 arms), the membership test dropping `isInMergeQueue`
  (1), the add-versus-removal comparison deleted (1), and the NOT-MEASURED
  wording collapsing into the never-enqueued wording (1).
