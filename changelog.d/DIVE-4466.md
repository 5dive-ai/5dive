## Unreleased — feat(plugin): market names the install unit, and the channel refusal fences the qualified ref (DIVE-4466)

`5dive market --kind=plugin --json` now says which unit each row installs into —
`installs: "agent"` for the chat channels that attach to ONE agent (telegram,
dashboard, buzz) and `installs: "box"` for everything `plugin add` installs on the
server. The dashboard's plugins panel could not tell them apart before and offered
all five with an Install button; `category` splits the wrong way and could not have
told it.

`plugin add` also refuses a built-in channel given as a QUALIFIED ref
(`telegram@5dive-plugins`), not only as a bare name. The refusal now runs before
resolution and before the trust gate, so it no longer depends on the plugin's own
manifest leaving `fivedive.trust.review` unset. A third-party marketplace that
publishes something called `telegram` keeps its ordinary path — the match is on
plugin and marketplace together.

The listing builds its rows in two places — the registered clone on disk and the
published manifest it fetches when a box has no clone yet — and both now read one
shared expression for `installs`, so a fresh box's catalogue cannot drift from a
warm one's.
