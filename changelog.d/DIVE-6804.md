## Unreleased — fix(task): a recurring reminder filed without --assignee is owned by the agent that filed it (DIVE-6804)

An agent that promised its owner a reminder filed `task add --recurring=…` with no
`--assignee`. The template fired on time, but the new row had no owner, so nothing woke it
and the owner never heard. Measured on even-branch 2026-10-23: DIVE-18 fired at 18:50Z into
DIVE-20 with an empty assignee. Templates were left unassigned on the promise that the
instance would be coordinated when it was cloned, but the materializer's clone copied the
empty column and nothing ever coordinated it.

Now `task add --recurring` with no `--assignee` stamps the filing agent as the template's
owner, so `task ls --recurring` shows one. When a template still has no owner (filed before
this release, or filed from a shell or a relay), the materializer gives the new row to the
template's filer if that is an agent, then to the filer's team coordinator, and logs it when
neither resolves. An explicit `--assignee` is unchanged.

`tests/recurring_template_owner_unit.sh` covers filing, an old unassigned template firing,
an explicit assignee, the coordinator fallback and the logged no-owner case; five of its
fourteen arms are red on the pre-fix tree.
