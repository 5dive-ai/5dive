## Unreleased — feat(browser): server mode and a one-time re-auth viewer, so a managed box needs no ssh, no apt and no display (DIVE-4118)

DIVE-4021 shipped `5dive browser auth` as "open a real Chromium, and REFUSE without a display". On
a managed 5dive VM there is no display and there never will be, so the only route through that
refusal was `ssh -X` plus `apt install chromium` plus a hand-written adapter JSON. lodar,
2026-09-09: *"thats too difficult for customers. the point was to make it easy to use for our paid
customers on our managed vm"*.

Server mode is the shape 4021's own design named as the DEFAULT and did not ship. The profile's
Chrome now lives on a **persistent Xvfb display owned by the seat**, and a person reaches it — to
log in the first time, and again when the site kills the session — through a viewer handed out as a
one-time ticket:

```
5dive browser serve <site>                                   # persistent Chrome on its own Xvfb
5dive browser viewer <site> --bind=<session> [--ttl=600]     # mint a one-time link
5dive browser viewer-redeem <site> --nonce=- --session=<id>  # the relay's gate; consumes the link
5dive browser viewer-revoke <site>                           # kill the view, keep the login
```

`auth` on a display-less box no longer dead-ends: it starts server mode and tells you to ask for a
viewer link. The old refusal survives only where it is true — a box that does not have the
server-mode packages, which now says *which* ones it lacks instead of half-starting.

### The question 4021 left open: what protects the session WHILE the viewer is open

A viewer onto a logged-in profile is not a screenshot. It is the credential with a keyboard
attached, so the answer is five properties and every one of them fails closed.

1. **Nothing listens off-box.** `Xvfb -nolisten tcp`, `x11vnc -localhost -once`, the websocket
   bridge on `127.0.0.1`. Redemption hands the relay a loopback target; the customer reaches it
   through the box's already-authenticated relay, never a port we opened.
2. **The ticket is a nonce we do not keep.** 32 bytes of urandom; the ticket file stores only its
   SHA-256, which is `gate-human-nonce-spec`'s rule for the same reason — a stored secret is a
   stealable secret. The raw value exists exactly once, in the line we print.
3. **It is single-use.** Redeeming consumes it. A TTL alone cannot close a replay of a link that
   leaked inside its window; single-use can, and the state check runs *before* the nonce compare so
   a spent ticket is not an oracle for a right or wrong guess.
4. **It is bound to the session that asked.** `--bind` is **mandatory** — there is no implicit
   unbound ticket, because "we will add the binding later" is how a bearer credential ships as one
   forever. `--bind=local` is the named escape for a hand-run on the box. A link redeemed from a
   different dashboard session is refused, and that refusal does not spend the ticket for the
   rightful one.
5. **The nonce never enters argv.** `/proc/<pid>/cmdline` is readable by the other seats on this
   box, so `viewer-redeem` reads the nonce from **stdin** and *refuses* `--nonce=<value>` rather
   than accepting it and hoping.

Killing the viewer does not kill the browser. The profile is the durable half and the view onto it
is the ephemeral half; that asymmetry is the design, and `viewer-revoke` says so in the words a
customer needs — the browser keeps running and stays logged in.

### A profile directory that already exists is now GRADED, not laundered

`auth` (and now `serve`) ran `mkdir -p; chmod 700; _audit`. On a directory that already existed
that `chmod` **repaired** a group-readable profile a moment before auditing it, so the audit could
never see the state it exists to catch — against the README's own rule that every command "re-audits
owner and mode and fails closed; it never repairs them". `_ensure_profile_dir` chmods only a
directory it just created and audits any directory it did not.

### Evidence

`tests/browser_plugin_unit.sh` grows the T10 block: **147 arms, 0 failed**, and the arms are graded
by **15 of 15 mutants killed** rather than by their count —

| mutant, i.e. the way the keyboard reaches the wrong person | suite |
| --- | --- |
| the ticket file keeps the raw nonce | 6 failed |
| redemption does not consume the ticket (a leaked link replays) | 2 failed |
| the expiry check is dropped | 2 failed |
| the session binding is not checked (a pasted link works) | 3 failed |
| a nonce in argv is accepted instead of refused | 2 failed |
| `serve` chmods an existing loose profile instead of grading it | 2 failed |
| the package precondition is deleted | 4 failed |
| `x11vnc` loses `-localhost` (it answers every seat on the box) | 1 failed |
| `websockify` binds `0.0.0.0` instead of `127.0.0.1` | 1 failed |
| `Xvfb` loses `-nolisten tcp` (the display becomes a remote keyboard) | 1 failed |
| `x11vnc -timeout` goes back to a constant shorter than the minimum TTL | 2 failed |
| redemption prints the target but withholds the VNC password | 4 failed |
| the nonce compare is moved AHEAD of the spent-state check (the oracle) | 2 failed |
| `serve --stop` leaves the ticket open (it redeems onto a dead port) | 1 failed |
| stopping the viewer leaves its password behind in the profile | 1 failed |

That last one **survived the first version of the arm** and is worth writing down: with
`_serve_requires` deleted, a box with no `Xvfb` still dies at the "did not start" check with the
same exit status and the same word in the message, so the missing-Xvfb arm graded nothing. A box
that HAS a display server and no chromium is what separates them — without the precondition the
launch runs with an empty binary name and a pidfile is written for a browser that never started,
which is "the tile says connected and there is nothing there". There is no X
server on a CI runner, so `Xvfb`/`x11vnc`/`websockify` are fakes on PATH — liveness is still the
real PID check and redemption is still the real SHA-256 compare; the only override is the X socket
*directory*, a path, which cannot make a dead display read as live. **Those fakes now RECORD their
argv** instead of `exec sleep 300`: written the first way they discarded `"$@"`, which silently
deleted the surface carrying the property this design leads with — dropping `-localhost`, binding
the bridge to `0.0.0.0` and dropping `-nolisten tcp` each changed nothing any arm could see. Every
flag-borne property above is now measured on the recorded argv, on this runner, with no `x11vnc`
present. The bare-box arm builds its
PATH by exclusion because this host does have Xvfb, and trimming PATH to `/usr/bin` passed that arm
against a box that had the packages.

### Not in this change, and owed

The packaging half is not here: `5dive-api scripts/install/apps.sh` does not yet preinstall
chromium/xvfb/x11vnc/websockify or run `5dive plugin add browser` + `browser setup` at provision
time, and the dashboard's Connect/Reconnect tile is not built. Server mode therefore ships **dark**
— reachable by hand on a box that has the packages, and not yet wired to a button.

### On-hardware arm, and the half of it that is still owed

This host has `Xvfb` and a real Chrome but no `x11vnc` and no `websockify`, so the arm splits:

- **RAN, against real binaries:** `serve` starts a real Xvfb (`:154`, socket present) with a real
  Chrome on it, both PIDs live; a second `serve` reports `already serving` rather than putting a
  second Chrome on one `--user-data-dir`; `--stop` reaps both **and the profile directory survives**
  — the durable/ephemeral split the whole design rests on; `viewer` on this box refuses, naming
  `x11vnc, websockify (novnc)`.
- **OWED:** the flags are now measured (the fakes record argv), but measured against a fake — no
  real `x11vnc` has been asked to honour `-timeout`/`-localhost`/`-passwdfile` here, `websockify`
  has never actually bridged, and no human has logged into a site through a real viewer. That arm
  belongs on a provisioned box (DIVE-4238), and it is the reason this ships dark rather than a
  footnote.

### Two blockers found in review, and the causes behind them (quinn, iteration 1)

- **The viewer died 30s into a ticket that advertises 60–3600s.** `x11vnc -timeout 30` was a
  constant sitting thirty lines from the TTL validator, and `x11vnc -timeout n` exits unless a
  client connects inside the first n seconds. Worse than expiring early: `viewer-redeem` still
  exited 0 and **consumed** the ticket, so the customer was left holding a spent link and a dead
  port. `-timeout` is now the ticket's `$ttl`, and two arms at two different TTLs grade that it
  tracks rather than matching one value by luck. Cause compiled:
  `community/wiki/a-lifetime-advertised-by-one-component-and-enforced-by-another-is-two-numbers.md`.
- **Nothing could ever authenticate to that VNC server.** The password was minted, written into the
  `0700` profile directory and handed to `x11vnc` via `-passwdfile` — and emitted by no verb, so the
  relay (which DIVE-4021's isolation deliberately stops from reading that directory) got a port that
  prompts for a secret nobody has. `viewer-redeem` now prints `target=` **and** `password=`: the
  redemption already has the right lifetime — one use, one bound session, consumed in the same
  breath — so the handover adds no new window. Cause compiled:
  `community/wiki/an-isolation-boundary-blocks-your-own-relay-so-the-handover-must-be-a-verb.md`.
- Folded in from the same review: `serve --stop` now revokes the ticket (one that outlives its
  viewer redeems 0 onto a dead port), and stopping a viewer removes its password file.
