## Unreleased — feat(plugin): `5dive plugin` — the install path plugins never had, and the contract it enforces (DIVE-4020)

There was no `5dive plugin` command. 47 top-level subcommands and none of them was `plugin`: a
plugin only ever installed as a **side effect** of another verb — `agent create` calls
`install_channel_for_agent`, `agent buzz enable` installs buzz — so a CLI-only self-hoster had no
way to discover or install one at all.

`5dive plugin add | list | remove | upgrade | enable | disable | rollback` and
`5dive plugin marketplace add | list | upgrade | remove` close that. Discovery deliberately does **not** get its own noun: it
folds into `5dive market --kind=plugin`, next to personas, so a user asking "what can I add?" does
not first have to know whether the answer is a plugin, a skill, a connector or a persona.

The verb is the enforcer for `community/wiki/the-5dive-plugin-contract-v1.md`, and each clause is
executable rather than described:

- **An undeclared surface is inert.** What gets registered is what the manifest DECLARED, never what
  the directory contains. A plugin shipping an `.mcp.json` it did not declare installs with that
  server unregistered — and is told so at install time rather than discovering it in a bug report.
- **The install path is keyed on the version**, so a change that did not bump `version` cannot
  arrive. Both places that hits (`add` on an installed version, `upgrade` against an unbumped
  source) say that in those words instead of printing "up to date".
- **Upgrade installs alongside and flips a pointer**, which is the only thing that makes the old
  version dir worth keeping — hence `plugin rollback`, a pointer flip rather than a re-fetch.
- **Uninstall is total**: every version, the pointer, the grants, the config stanza.
- **Enable/disable is a flag flip, not a re-copy** — `disable` drops the pointer and leaves the
  version-keyed dir alone, so turning a plugin back on needs no network, no marketplace and no
  consent screen. It exists because `plugin list` renders an ENABLED column, and a column that can
  only ever say "yes" is a claim the product cannot honour. `rollback` respects it: a disabled
  plugin stays disabled, because "roll back to the version that worked" is not also "switch it back
  on".
- **Consent before code.** `add` prints who published it, its review tier and the exact grants in
  plain English ("your microphone and speakers"), and refuses on a non-interactive stdin rather than
  defaulting to yes on exactly the path where nobody is watching.

**Third-party plugins stay closed**, per lodar's 2026-09-07 decision. Only `official` installs. That
is a refusal, not a warning, and there is deliberately no `--allow-unreviewed` flag: a plugin runs as
the agent with the agent's credentials and no sandwich of ours separates them, so opening the door
needs the host-shipped trust root, counter-signed key enrollment and revocation list in contract
§5.1 — none of which is built. Our own `telegram`/`dashboard`/`buzz` predate the contract and are
installed per AGENT, so `plugin add` points at `agent create --channels=` instead of refusing them
with a provenance lecture.

`voice` ships bundled as the reference implementation and registers itself as the marketplace
`5dive`, so `5dive plugin add voice` resolves with no network and no GitHub credential. Its runtime
is real — `5dive-setup-voice` installs ffmpeg, faster-whisper and edge-tts plus a warm transcription
service on :8765, and speech never leaves the box — and this is the CLI path to what the dashboard
already offers as the **Voice** connector, for self-hosters who have no dashboard.

That host-level step is **printed, never executed.** A new `fivedive.setup` manifest block (a
proposed §6 addendum) carries a hint and a command, and `plugin add` shows them and stops. It is not
a post-install hook and must not become one: running a string out of a manifest is arbitrary code
execution chosen by the publisher — the door §5 keeps shut — and worse than that door, because it
runs before the user has seen what they installed. `voice` is our own plugin and gets no exception;
an exception for the first plugin is how the rule means nothing by the tenth. A negative-control arm
(the fixture's setup command writes a sentinel file; the arm asserts the file does not exist) is what
keeps that true.

The store lives under `$STATE_DIR/plugins` rather than the contract's `~/.5dive/plugins`: on a box
with ~18 agent seats a per-home store copies the same plugin once per seat and gives each a separate
copy to revoke, and every other piece of 5dive state is already host-level.

**Iteration 3 fixes (quinn's reject).** Three previously-green corpus harnesses went red on the
branch and are green again:

- `plugin rollback` died on its own probe. With exactly ONE version on disk `grep -vFx "$cur"`
  matches nothing and exits 1, and under `set -euo pipefail` the assignment killed the process on
  that line — so the friendly *"no other version is on disk"* refusal below it was unreachable and
  the command exited 1 with nothing on stdout or stderr. One version on disk is not an edge case; it
  is every install that has never been upgraded, i.e. the first thing a user reaches for after their
  first upgrade goes wrong. Fixed with `|| want=""` per `scripts/unguarded-probe-scan.sh`.
- `_plugin_register_bundled` ended on a conditional, so a false one would supply the function's exit
  status and take its errexit-running caller down with no message. Explicit `return 0`.
- `market`'s new `--kind` refusal read as an enumeration of the sibling subcommands below it
  (`usage_enumeration_completeness_unit` associates any `$E_USAGE` string with a pipe in it within
  six lines above a `case`). Reworded to name the choices in words — better copy, and it stops
  claiming to enumerate something it does not. The subcommand aliases are now documented in
  `_market_usage`, where they belong.

Also: the built-in channel hint (`plugin add telegram` → *"use `agent create --channels=`"*) moved
**before** marketplace resolution. It sat behind the trust gate, which sits behind manifest
resolution, which needs a marketplace the user has not added — so on a fresh box the hint never
fired and the user got a setup error they could not act on.

**And the harness gained the shell it was missing**, which is the finding rather than the three
symptoms: this suite runs `set +e` so that `fail` does not kill it while grading refusals, which
also switches off the only rail that makes an unguarded substitution fatal. 86 green arms could not
have seen `rollback` dying. The new T12 block runs those paths inside a plain
`( set -euo pipefail; … )` — never as an operand of `||`, where the exemption would propagate in and
make the death unreachable — with a positive control proving that shell can still kill.
