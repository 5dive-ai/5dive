## Unreleased — fix(agent): every seat start fixes its login's read perms, and a clean start clears the stale warning (DIVE-8195)

An antigravity seat no longer stays DEGRADED after the nightly update. The update
restarts seats with a plain `systemctl restart`, and only `5dive agent restart`
re-opened the account token for the seat, so the seat booted on a token it could
not read. The seat unit now runs that step as root before every start (nightly,
reboot, crash re-start). And once the token is readable and the seat's copy is
current, the start clears the old warning, so `doctor` and `auth status` stop
saying "stale". A copy that really failed keeps its warning. Openclaw seats get
the same clear.
