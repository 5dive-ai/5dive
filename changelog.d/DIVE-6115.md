## Unreleased — fix(reflex): a standard seat reaches reflex through root, so `config openrouter-key=-` reaches clicker (DIVE-6115)

On a self-hosted box, `sudo 5dive config openrouter-key=-` set the key and root's
`reflex status` said configured, but a hired standard seat such as clicker read
"configured unknown (cannot see the key file)". The key is 640 root:claude-keys
since DIVE-5690, and the seat is not in that group, so the browser's broken-step
retry and its new-site login drafts silently fell back to the name match.

The standard seat template now grants `5dive reflex status`, `reflex pick-ref`
and `reflex login-marker` as root, each bare and with arguments. The key is read
root-side and only the decision comes back, so DIVE-5690's rule holds: no
standard seat reads a box key. A seat's own `reflex status` re-runs itself
through that grant when it cannot see the key, so it reads configured true.
Because a wildcard grant hands the seat's arguments to root, a call from a seat
that does not hold the whole CLI is narrowed first: the built-in backend only,
no `--out` file, and every input file read as the seat. Admin seats and the
owner are unchanged.

Setting the key before or after a hire ends the same way. Seats hired before
this release gain the grant from the installer's sudoers reconcile on update.
`config --help` now says what the file is: 640 root:claude-keys.
