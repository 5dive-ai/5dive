## Unreleased — fix(bug): a seat that cannot read the box key sends its report keyless instead of spooling it forever (DIVE-7248)

On one of 5dive's boxes, a seat other than root cannot read the box's key, so an owner-approved `5dive bug --file` from it stopped with "this seat cannot read the box's key" and saved the report locally. Only that same seat could send the saved copy, and it hit the same wall every time, so the report never left. Such a seat now sends the report the way a self-installed box does, without a key, and sends anything it saved earlier along with it. A seat that can read the key still sends with it.
