## Unreleased — feat(local): the office server installs and serves the 5dive app; one private file installs server and app together (DIVE-8809)

`sudo 5dive local app install <file>` installs the office app (the 5dive app built for an office server) and the server opens it at its own address. The app file is checked first: it must be signed by the office app key that 5dive's root key certified for that one purpose, so a changed file, an update key's signature, another root, or an expired or revoked key are each refused. A server with no root key refuses every app file. The app is unpacked root-owned under `/opt/5dive/office-app/<version>` and served at once, with no restart. The version before it is kept, so `--allow-downgrade` can go back one step. `5dive local app status` says which app is served.

A signed-in device that opens the server now gets the app. A signed-out one gets the sign-in it had before (a code, or a join link), and lands in the app once in. The old page stays at `/lite`. The app's own Sign out (`DELETE /api/proxy/me`) signs out that device only.

The private "Office server" file (`packaging/offline/build-office.sh`) is the USB installer with the app file inside it. It installs 5dive, then the app. The same file updates a running server, from the panel's Update screen or `local app install`. The public USB file and the public update file never carry the app.
