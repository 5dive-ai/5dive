## Unreleased — feat(agent): `agent config <name> set chrome=on` gives one agent Claude in Chrome on its own claude.ai login (DIVE-6345)

Claude Code switches Claude in Chrome off on a setup token: the token's scope is `user:inference`
only, and every seat runs on one. `chrome=on` (claude agents only) turns the extension on in the box's
Chrome policy (`5dive browser claude enable`, browser plugin 1.44.0) and stamps `AGENT_CHROME=1`.
Once the agent has its own login (`5dive browser claude connect`: one claude.ai sign-in and one
Authorize tap on the owner's phone), the launcher starts it with `--chrome` and with the env tokens
unset, so it runs on that login. With no login yet it starts as before, on its token with Chrome off,
and says how to connect. The nightly creds heal never renames an opted-in agent's login file: it
refreshes itself, and an old `expiresAt` only means the agent was stopped. `chrome=off` takes the
agent back to the shared token at its next restart.
