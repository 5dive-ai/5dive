## Unreleased — feat(agent): `agent _telegram_open` lifts Telegram's owner-only lock on a seat's own bot (DIVE-6930)

The owner can now let someone write to the agent from chat: the telegram plugin's `access_request` tool sends the owner Allow / No, and only the owner's tap adds the person. A bot that 5dive's (or a partner's) manager bot made only answers its owner until the manager lifts that lock, so after the tap the plugin runs `sudo 5dive agent _telegram_open`.

- **One POST, as root**, to 5dive-api `POST /server/telegram/agents/<agent>/open` with the box identity. Nothing is written on the box; access.json stays the gate.
- **Only its own bot.** A standard seat holds one exact-path, no-args sudoers line (`render_standard_sudoers`, carried to existing seats by `agent _reconcile_sudoers`), and the agent is derived from `SUDO_UID`. Root may name an agent.
- **Answers:** `open`, `not_managed` (a BotFather or CoS bot has no lock) and `no_account` (a box with no 5dive account) succeed; anything else fails with the API's reason.

`tests/telegram_open_unit.sh`: 21 arms (the grant renders once and classifies as standard in both classifiers; the verb's seat derivation, refusals and answers over a fake API).
