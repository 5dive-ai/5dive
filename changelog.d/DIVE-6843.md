## Unreleased — fix(agent): an agent can no longer build a new agent on the box's free demo AI (DIVE-6843)

On a fresh box a lead agent made a new agent on the free demo AI, and one research run used all
of it: the lead's own chat stopped, and the owner never got the answer. `agent create` now
refuses when an agent asks for the demo AI, either by its account name (`--auth-profile=demo-ai`)
or by passing its key under another name. The refusal says what to do instead: create the agent
with `--defer-auth` and send the owner the sign-in link from `agent auth start`.

- **Who counts as an agent:** a `sudo` call from anywhere except the dashboard and Mini App (the
  box's shell service) or a person's own login. The owner's hires from the app still start on the
  demo AI, as before. Box setup, which runs as root, is not affected.
- **Imports:** an agent's `agent import` no longer picks the demo AI by default; the new agent
  waits for its own sign-in.
- This is a guard on the normal path, not a lock: an agent with full root can still get round it.
