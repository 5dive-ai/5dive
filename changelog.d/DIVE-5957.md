## Unreleased — fix(doctor): probe the auth profiles seats run on, not only the default credential (DIVE-5957)

`5dive doctor`'s auth check probed only each harness's default connector credential. On a box
where every seat sits on a named auth profile, a dead default token showed a red
`auth/claude: credentials rejected by provider — re-auth required` for a credential no seat
reads. The reverse was worse: a seat whose own profile token was dead read `auth/claude: ok` as
long as the default worked.

doctor now probes each distinct (type, profile) pair a registered seat is bound to, once per
pair however many seats share it, and reports it as `auth/<type>:<profile>` with the seats and
the profile-scoped `agent auth login … --auth-profile=<p>` command. The default credential
(`auth/<type>`) is probed only when some seat of that type has no profile; otherwise it is
reported `ok`, unprobed, with the reason named. An unreadable registry keeps the hard error on
the default path, as before.

`tests/doctor_auth_profile_pairs_unit.sh` drives `doctor --category=auth` with a fixture registry
and a stubbed probe that answers by profile. On the pre-fix tree 8 of its 11 assertions go red
(both directions); the three that stay green are the preserved behaviour (default in use,
unreadable registry, unused harness).
