## Unreleased — feat(sysadmin): `5dive sysadmin`, a partner box's privileged work behind the owner's tap (DIVE-5187)

A persona agent on a partner box is a standard seat: no sudo, no services of its own, no config
edits. A client who asked for a shared plan page got "I don't have the access". Giving every agent
sudo was not an option: each one reads untrusted text, so one injected page would be root on the box.

One seat, `sysadmin`, does that work for the others. `5dive sysadmin install` (root; 5dive-api runs it
when it builds a partner box) creates it with no channel and no heartbeat, writes its rules where the
seat cannot edit them, and gives it one root grant: `5dive sysadmin _broker`, exact arguments,
parameters on stdin. The broker enforces every rule, so none depends on the seat's own prompt:

- `read` runs a script now as `nobody` with the log groups (status, logs, ports; no changes).
- `restart <agent>` restarts one agent's service.
- `propose --for=<agent> --summary=<line>` sends that agent's owner the summary and the first lines of
  the script, with Approve / Decline, in the agent's own chat. Nothing runs before the tap. The buttons
  are the owner-ask ones (bap/bdn), so the relays that already carry browser asks to root carry these.
- `owner-ask tap` finds the request, checks the tapper, the proof and the 30-minute TTL, spends the
  proof, and starts the script as root in a sandbox. That sandbox hides /etc/5dive, /var/lib/5dive,
  every home and sudoers, makes sshd and firewall config read-only, and drops CAP_SYS_ADMIN,
  CAP_SYS_PTRACE and CAP_NET_ADMIN. Then it wakes the seat. `status [<sa-id>]` reads the result.
- A proposal that names a secret, sudo, SSH, the firewall, the box's accounts or encoded text is
  refused before the owner is asked.

The approvers are pinned root-side. An agent's access.json is its own file, so an injected agent could
add a stranger there. `agent create` and `agent config set telegram.allowed-users` now record the ids
root set (`telegramOwners`), and only an id on both lists can approve. `agent create` also turns on
linger for the seat user, so an agent's own `systemctl --user` app keeps running.

Standard seats get one more grant, `5dive --json owner-ask tap *`: the Telegram plugin relays an owner's
tap on the agent's own bot with it, and without it every such tap failed on a standard seat. On a warm
spare the seat is built before the box has a key; it waits on the seeded account, and the claim's
`account set` binds it.

`tests/sysadmin_unit.sh` has 64 arms (one needs root and systemd). Two mutants: without the pin,
a tap from the id the seat added runs the script; without the lint, "print the OpenRouter key" reaches
the owner.
