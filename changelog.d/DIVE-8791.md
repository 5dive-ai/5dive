## Unreleased — fix(agent): `telegram-access set` lets a new person past Telegram's owner-only lock (DIVE-8791)

A bot that a manager made (a Connect tap) answers only its owner until 5dive lifts that lock. `5dive agent telegram-access set` wrote the new person into access.json and printed OK, but never lifted the lock, so Telegram kept refusing them ("The owner of this bot has restricted access") while `telegram-access get` listed them.

Now a `set` that adds an id the file did not have also lifts the lock (the same call as `5dive agent _telegram_open <name>`) and says what happened: `data.open_state` is `open`, `not_managed` (a BotFather bot, no lock), `no_account` (a self-hosted box, no lock) or `failed`. On `failed` the write is kept, the command still exits 0, and it prints one line: Telegram still blocks everyone but the owner, and the retry. A `set` that only removes ids or re-saves the same list makes no call (`open_state: skipped`).
