## Unreleased — feat(chat): encrypted chat on 5dive servers, the CLI side (DIVE-7502)

An agent on a 5dive server replies through the dashboard relay, which had no encrypted ops, so a
sealed reply failed closed. `5dive _dashboard_relay` now has `event-e2e <chat> <envelope> [file]...`
and `status-e2e <chat> <0|1> [envelope]` (the ops dashboard@5dive-plugins already calls). They post
only ciphertext: the body must be one box-to-browser envelope (64 KiB; a status 8 KiB), each file a
sealed `<agent>-*.e2e` blob in the outbox whose bytes are an envelope too, and the message is marked
`e2e {v:1}`. A plain file never rides an encrypted reply. `put` already takes those blobs.
`chat e2e enable -` and `chat devices sync` work on a 5dive server as they do on a self-hosted one
(same box token); 5dive.app runs them over the exec rail, the secret on stdin. Wording no longer
assumes a link line. Harness: `tests/chat_e2e_unit.sh`.
