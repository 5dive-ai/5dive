## Unreleased — fix(task): a small or docs-only delivery books no grader at `task deliver`, and a CI-graded row can be merged (DIVE-6223)

`5dive config verify-small=<lines>` and the docs-only rule were only checked by `task done`. Pull
requests are delivered with `task deliver`, which sent every delivery to a grader. On 2026-10-14 a
one-file README change of 76 lines waited in the grader's queue on a box set to `verify-small=150`.

`task deliver` now runs the same two checks before it attaches a grader. The checks are the
docs-only rule (only tests, docs or changelog files) and the size rule (under the threshold, with no
path from the blast-radius denylist). If either one applies, no grader session is booked. The row
is recorded as graded by CI (`graded_by=ci:docs-only` or `ci:small`). Its graded sha is the
delivered head. It goes to the box's merge seat as merge owner. Two kinds of row are still graded:
rows filed with `--verify` (this now also wins over the docs-only rule), and rows pinned to a named
grader with `--review=<seat>`. A row that binds companion pull requests is also still graded, and
so is a row whose grader rejected it or recorded a FAIL, even when the fix made the diff small.

The file list and line counts come from the read `task deliver` already makes to check that the
pull request is visible, so a delivery still costs one GitHub request. If that read is switched off
or returns no file list, the delivery is graded as before.

A CI-graded row can be merged by its merge owner and by no other seat. `task merge` on such a row
checks the pull request first. The head must be the graded sha, every required check must be green,
and no changed path may need a person's review. If any of that fails, nothing is merged.

A `review=check` row whose command passed could get stuck in the same way. This happened when the
row had already recorded its maker, for example after an earlier delivery to a temp grader. The pass
was credited to the maker's seat. A maker's own grade gives no seat merge standing, so `task merge`
refused, and the row was handed back to the grader by hand. That pass is now recorded as
`ci:command` and handed to the merge seat.

`tests/deliver_small_ci_grade_unit.sh` covers this end to end through `task deliver`. A 76-line
README delivery and a 40-line code delivery get no grader. In the control cases, a 290-line
delivery, a 5-line shared-library change, a `--verify` row, a row pinned to a seat, a row with
companions, `verify-small=off` and `verify=never` all keep their existing behaviour. The harness
also covers merge standing, with a control showing that a seat-graded row grants nothing. Eight
mutants, each removing one of these parts, turn it red.
