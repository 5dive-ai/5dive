## Unreleased — fix(task): a loop row whose fix went into the same pull request closes on the graded sha

A grader closing a reworked loop row was refused with "its delivery binding was recorded at loop
iteration N" whenever the maker pushed the fix to the same pull request and re-delivered with
`task done`, which never re-stamps the binding. Ten rows needed an extra maker round on 11-19..11-20
for this alone. The close now reads the bound pull request's head: when it is the sha the grader
states in `graded-sha:`, the binding is current and the close goes on. A fix that moved to a
different pull request (DIVE-2057), a missing `graded-sha:`, or a read that does not answer still
refuses as before.
