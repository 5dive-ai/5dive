## Unreleased — fix(models): agents follow each Claude release instead of staying on the model they were hired on (DIVE-6788)

Every hire that asked for "sonnet" or "haiku" was pinned to the id the catalogue held that day, and the catalogue missed the Sonnet 5.5 and Haiku 5.5 releases for a week, so new seats started on Sonnet 5 and Haiku 4.5.

- `model_latest` now maps sonnet to `claude-sonnet-5-5` and haiku to `claude-haiku-5-5`.
- Every self-update runs `agent _float_models`, which moves a booted seat still on a model we pinned (a current or previous default) to the bare family alias. Claude Code resolves the alias itself, so the seat moves to each new release with no catalogue bump. The seat keeps the effort it ran at; the level is also written under the alias key, which Claude Code applies to whatever the alias means after a release. A model somebody chose, a seat on an OpenRouter or other mapped account, and a seat that has never booted are left alone.
- The BYO `anthropic` defaults for hermes and openclaw and the account rotation probe read the catalogue instead of naming a release; `src/lib/models.sh` is the one file with a Claude id in it.
- A daily check (`claude-model-latest.yml`) opens an issue when OpenRouter lists a newer Claude, or a new Claude family, than the catalogue.
