## Unreleased — fix(agent-start): 0.26.1 emptied every box — a self-referencing `local` killed every agent unit (DIVE-4067)

**0.26.1 could not start an agent. Any agent, on any box, unconditionally.** The nightly installs the
release and then restarts every agent, so a box that took 0.26.1 went dark on its own, with nobody
touching it. Upgrade to 0.26.2 before the next nightly, or the box empties again.

One line, added to `5dive-agent-start` by DIVE-4036:

```bash
local dir="$HOME/.5dive" f="$dir/delivery.env" tmp
```

`local` is a **builtin**: bash expands all of its arguments before performing any of its assignments,
so the `$dir` in the second word resolves against the **enclosing** scope, not against the `dir=`
standing beside it. `write_delivery_declaration()` has no caller holding a `dir`, and the launcher
runs under `set -euo pipefail`, so this is a fatal `dir: unbound variable` before the pane is ever
started. Every unit failed identically, systemd gave up after the restart burst, and `5dive agent
list` read `failed` for the whole fleet. The fix is three statements instead of one.

**Nothing in the release path could have seen it, and that is the part worth fixing.** `bash -n`
accepts the file — the syntax is valid and the defect is in evaluation order. The unit corpus sources
functions and never runs the launcher. `install-smoke` installs the bundle but does not start an
agent and watch it stay up, so a launcher that exits 1 on its 1687th line reads as a clean install.
And `5dive doctor` hashes `/usr/local/bin/5dive` — it reported `cli-provenance` OK while the launcher
sitting beside it was fatal, because the launcher is not in that hash.

So the one-line fix ships with `scripts/local-selfref-scan.sh`, which reads the shipped shell (the
launcher, the installer, `src/`, `scripts/`, the host scripts) for any declaration builtin — `local`,
`declare`, `typeset`, `export`, `readonly` — whose value expands a name declared in the same
statement. `tests/local_selfref_scan_unit.sh` grades it in both directions and reds if the shape
returns.

**The scan found three more on its first run, all of them shipped, none of them noticed.**
`fork_stage_one()` and `fork_content_matches()` in `5dive-stage-fork-plugins.sh`, and
`write_admin_sudoers()` in `src/cmd_agent_create.sh` — which composes the path of a file it writes
into `/etc/sudoers.d`. All three were surviving on luck: each one's caller happens to hold a variable
of the same name carrying the same value, so bash's **dynamic** scoping resolves them correctly by
coincidence. Rename a caller's loop variable and `write_admin_sudoers` begins writing an admin
`NOPASSWD` grant to a path derived from a different agent's name. Fixed here alongside the launcher;
they are the argument for the scanner rather than a footnote to it.

Known residual, named rather than papered over: the scan covers shipped shell only, not `tests/`. A
self-referencing `local` in a harness is still a bug, but it fails where somebody is looking, and
reding every PR on pre-existing harness debt is how a guard gets switched off in a week. Pass paths
explicitly to scan outside the default set. And the scan is a **text** check — it cannot tell a fatal
instance from one a caller happens to cover, so it accuses both. That is deliberate: which of the two
you have is decided in another file, and can change without touching this one.
