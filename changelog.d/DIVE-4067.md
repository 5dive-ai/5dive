## Unreleased — fix(agent-start): 0.26.1 emptied every box — a self-referencing `local` killed every agent unit (DIVE-4067)

**0.26.1 could not start an agent. Any agent, on any box, unconditionally.** The nightly installs the
release and then restarts every agent, so a box that took 0.26.1 went dark on its own with nobody
touching it. Upgrade to 0.26.2 before the next nightly, or the box empties again.

One line, added to `5dive-agent-start` by DIVE-4036:

```bash
local dir="$HOME/.5dive" f="$dir/delivery.env" tmp
```

`local` is a **builtin**: bash expands all of its arguments before performing any of its assignments,
so the `$dir` in the second word resolves against the **enclosing** scope, not against the `dir=`
standing beside it. `write_delivery_declaration()` has no caller holding a `dir`, and the launcher
runs under `set -euo pipefail`, so this is a fatal `dir: unbound variable` before the pane is ever
started. Every unit failed identically, systemd gave up after the restart burst, and `5dive agent
list` read `failed` for the whole fleet. The fix is three statements instead of one.

## We already owned the instrument, and it was configured off

The tempting write-up here is "no check could have seen it". That is false, and the true version is
more useful.

`shellcheck` names this defect exactly — **SC2318**, *"this assignment is used again in this 'local',
but won't have taken effect. Use two 'local's."* The `shellcheck` job in `install-smoke.yml` is a
**required** status check on `main`, and it already linted `5dive-agent-start` **by name**. SC2318 is
classed a *warning*; that job runs `-S error`; the severity filter dropped it. The check ran, passed,
and was green on the commit that emptied the fleet.

So this release adds a second pass over the same files — `shellcheck --include=SC2318`, wired to the
job's exit code — which makes that one code a merge blocker at any severity. `--include` restricts to
the codes named, so it cannot be folded into the `-S error` invocation without losing the error
coverage; and dropping those passes to `-S warning` would light the tree up at once, and a gate that
is red on arrival gets disabled. One code, promoted deliberately, stays green.

**Measured** (shellcheck 0.9.0, 2026-09-08): 4 findings at `main` d36b40ce — `5dive-agent-start:1695`,
`5dive-stage-fork-plugins.sh:95` and `:182`, `src/cmd_agent_create.sh:171` — and **0** after this
commit. The added pass costs ~82s on that job, roughly doubling its shellcheck time; most of it is one
15k-line file in `src/`, because shellcheck's time and heap are superlinear in the size of a single
parse unit.

## The other three, and why they were invisible

`fork_stage_one()` and `fork_content_matches()` in `5dive-stage-fork-plugins.sh`, and
`write_admin_sudoers()` in `src/cmd_agent_create.sh` — which composes the path of a file it writes
into `/etc/sudoers.d`. All three were surviving on luck: each one's caller happens to hold a variable
of the same name carrying the same value, so bash's **dynamic** scoping resolves them correctly by
coincidence. Rename a caller's loop variable and `write_admin_sudoers` begins writing an admin
`NOPASSWD` grant to a path derived from a different agent's name. Fixed here.

Two of those four lived in `5dive-stage-fork-plugins.sh`, which — along with `5dive-refresh-plugins.sh`
and `5dive-refresh-skills.sh` — is installed to the box, runs there, and was **linted by nothing**.
The same gap DIVE-2125 closed for `scripts/`, one directory out. The file set is widened here, and
`tests/shellcheck_sc2318_gate_unit.sh` reds if either the pass or those three files leave it.

## What is still owed, and it is not in this release

Nothing in the update path notices that the box it just updated is now dark. `install.sh` grades the
**artifact** — it fetched, the sha matches, `bash -n` passes — and never the **outcome**; `5dive doctor`
reported `cli-provenance` OK on a box with zero running agents, because it hashes `/usr/local/bin/5dive`
and the launcher beside it is not in that hash; and `install-smoke` installs the bundle without ever
starting an agent and watching it stay up. A post-install health gate with rollback is filed
separately (DIVE-4068) and is the thing that turns "a bad release empties the fleet" into "a bad
release costs one restart and a rollback line".
