## Unreleased — fix(gate): a lint refusal inside `task need` fails its own arm instead of aborting the harness, and a person-facing gate's buttons must name outcomes (DIVE-4462)

Two changes, and the order between them is the whole point.

**The seam, first.** `fail()` ends in `exit`. Eighty-one harnesses under `tests/` source `src/` and
call `cmd_task_need` in their own shell, so ANY refusal added to that function killed them — at
rc=3, before their summary, with every assertion after the call SKIPPED rather than passed. That is
not a cost of any one rule: it is a property of the seam, inherited by the next refusal anyone adds.
Measured on DIVE-4431's branch: one new refusal aborted ten harnesses across all three
`core-pristine` shards, and `gate_verifier_route_unit` died after 3 of its 22 arms. Ten reds were
not ten defects — they were ten harnesses whose remaining coverage silently stopped existing.

`tests/lib/gate_seam.sh` re-binds `cmd_task_need` to a wrapper that runs the real function in a
subshell, so `fail`'s `exit` ends the subshell and returns its code to the caller. **Call sites are
untouched** — the fix is one source line per harness, not a sweep of the 46 fixtures that pass the
bare-letter `--options` idiom. The refusal still refuses, still prints, still returns 3; it just no
longer takes the harness with it. `tests/proof_publish_gate_unit.sh` is the one deliberate
omission: it stubs `cmd_task_need` outright and never reaches the real one.

**Then the rule the seam had to hold.** On a gate whose RESOLVED ROUTE is the paired human,
`--options=A|B` is now refused. Those options are the buttons, and a button reading `A` names no
outcome: once the ask is forwarded, quoted or screenshotted, "recommend: A" is a token with no
dictionary, and the mapping survives only in the clause order of a sentence read on a phone. On
2026-09-13 that is exactly what lodar's phone showed.

Keyed on the resolved route, not the declared tier (DIVE-4431), and carrying the same documented
`--ask-ok` escape as the readability and answerability refusals beside it — a gate must never become
unfileable (DIVE-2216) and an exception nobody can count is a warning with extra steps.

**DIVE-4416's warning is unchanged for the agent reader.** "Warn, never fail" was deliberate:
fixtures and scripted callers (DIVE-2249) file letters on purpose, and turning that warn into a
blanket refusal is what reds the fleet. The refusal lives inside the `_ar_human` block; below it,
nothing moved.
