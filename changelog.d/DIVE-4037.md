## Unreleased — fix(usage): report plan consumption beside API-equivalent cost (DIVE-4037)

`5dive usage` reported what a workload would have **cost on the API**, not what it **consumed of the
plan**, and only the second one runs out. The headline `TOTAL` was `input + output + cache-write`
with cache-read deliberately excluded — defensible when the question was money, wrong now that we
run on flat-rate subscriptions. Measured 2026-09-07 on this fleet: `main` showed **11.7M against
536.4M actually moved**, a 46x gap, so ~98% of what the plan meters was invisible. Every capacity
surprise that week happened while `usage` looked comfortable.

There are now **two named columns, and neither is the old one renamed**: `API-EQ` is bit-for-bit the
number that used to sit under `TOTAL`, and `QUOTA` (all four token classes) is beside it, with the
key on the same screen as the table. Every derived figure picks a basis explicitly and they differ
per figure — `TOP AGENTS` order and `SHARE` go quota (`SHARE` apportions the vendor's own 7-day
percentage, and that gauge meters the plan, so cost weights hand the percentage to the wrong seat),
`TOP TASKS` order stays cost, because "which task was expensive" is a value question.

The alert path is wired to the figure that can predict a wall: budgets carry a per-budget `basis`,
`budget check` enforces the declared one, and the alert names it. **Existing thresholds are NOT
re-based** — each was chosen against the old figure, so reading it on quota multiplies measured burn
~46x against an unchanged number and would trip every ceiling at once. An absent basis normalizes to
`cost`, only new budgets default to `quota`, and the residual is loud instead of silent: `cost` names
each cost-basis budget that cannot fire before the plan runs out, with the ratio and the one-command
fix.

**Absence renders as absence.** An older payload with no `quota` field prints `?` in the cell on both
surfaces that render one — never the API-EQ number under a header reading "what runs out", which
would be a ~46x understatement the reader believes.

Known residual, named rather than papered over: `quota` is an **unweighted** token sum, i.e. an
upper bound. The cache-read weight is declared per provider in the JSON payload — **measured** on
Codex (DIVE-4028, n=1: 14,016,606 tokens, 98.2% cache reads, 9% of a weekly pool) and **assumed** on
Claude, where we have no gauge-versus-token measurement. A Codex seat's tokens also reach the agent
row and no task row: Codex logs cumulative per-rollout snapshots, which cannot be truthfully
assigned to a task window, so `sum(tasks[].quota)` is not fleet plan burn on a mixed fleet. The
payload says all of that by name.
