## refactor(task): split the 15,039-line `src/cmd_task.sh` into `src/task/*.sh` (DIVE-3278)

`src/cmd_task.sh` was 15,039 lines — **19% of the whole source tree**, and roughly
three times the next-largest file. It is now eleven files under `src/task/`, one per
concern:

| file | lines | what lives there |
|---|---|---|
| `dispatch.sh` | 599 | usage text, the `cmd_task` subcommand dispatcher, worktree reclaim-on-close, the `set-*` mutators, `task init` |
| `routing.sh` | 742 | coordinator / deputy / QA resolution, verify-skip reasons, delivery paths, lane + WIP-cap arithmetic, the filing cap, assignee resolution |
| `crud.sh` | 1,079 | `add`, `ls`, `show`, `gate-history`, `assign`, `verifier` |
| `gate_evidence.sh` | 1,663 | GitHub token discovery, the anonymous probe rail, and every PR / branch / sha / version reference pulled out of a task's text and graded against its real state |
| `status.sh` | 1,876 | the result-over-closed guard and `_task_status_cmd`, which `start` / `done` / `cancel` all funnel through |
| `delivery.sh` | 680 | `deliver`, `reject`, the maker→verifier routing hop, the merge audit |
| `loops.sh` | 1,003 | the loop board, loop advance / cascade-unblock, `verify`, `block` / `unblock` / `park` / `unpark` |
| `need.sh` | 3,382 | `task need` — every predicate deciding whether a gate needs a human, which seat may clear it, what tier it floors to, plus the filing verb |
| `notify.sh` | 1,703 | channel resolution, the escalation chain, Telegram delivery of a filed gate, reply markup, button retirement |
| `inbox.sh` | 579 | coordinator, human inbox, inbox send, gate proof, clear-recs |
| `answer.sh` | 1,734 | bounce detection, the tap log, delegated answers, `task answer`, `task escalate`, `task rm` |

**Not one line of `task` logic changed.** The split is a pure partition at
function boundaries (comment blocks travel with the function they document).

### `src/cmd_task.sh` is now a loader — dead code in the bundle, load-bearing in the split tree

This is the idiom `src/lib/self.sh` already uses (build.sh's "Order matters" note;
`community/wiki/command-v-answers-the-wrong-question.md` rule 5). `build.sh` cats
every `src/task/*.sh` **ahead of** `src/cmd_task.sh`, so by the time the bundle
reaches the loader every `declare -F` guard is already satisfied and nothing is
sourced. In the split tree nothing has been cat'd, so the `source` calls fire.

That is what let this land **without touching a single one of the ~60 tests that
do `. "$SRC/cmd_task.sh"`** — they still get the whole of `task` from one source
line. The `src/task/*.sh` order in the loader is kept identical to `build.sh`'s,
because a handful of files open with top-level `readonly`/regex assignments that
later files read.

### The bundle is provably unchanged apart from added comments

`build.sh` output before the split vs. after:

```
lines removed from the old bundle: 0
lines added:                     107   (11 file-header comment blocks + the loader block)
```

Zero removals and zero reordering — every one of the 15,039 original lines is still
present, in its original position, in its original order. `bash -n` clean; the
rebuilt bundle was run against the live board (`task show`, `task ls`) before commit.

### The real risk was text-SCANNERS going blind, not sourcers breaking

A harness that greps `src/*.sh` (non-recursive) silently stops seeing `src/task/`,
and a scanner that finds nothing reports **green**. Swept and retargeted:

- `scripts/scan-trailing-conditional.sh`, `tests/local_array_unbound_default_unit.sh`,
  `tests/gate_json_envelope_unit.sh`, `tests/gate_channelless_escalation_unit.sh`,
  `tests/usage_enumeration_completeness_unit.sh` — `src/*.sh` globs widened to include
  `src/task/*.sh`.
- `tests/audit_task_store_classification_unit.sh`, `tests/gate_parity_smoke.sh` —
  explicit `src/cmd_task.sh` file lists widened.
- `tests/task_done_cited_preclose_unit.sh`, `tests/gate_proof_verify_history_unit.sh`,
  `tests/gate_evidence_form_mutation.sh` — mutation harnesses that `sed` an anchor into
  `src/cmd_task.sh`. Retargeted across the whole set, **keeping** the "exactly one
  occurrence" requirement as a count over the set rather than per file, so a duplicated
  anchor still fails.
- `tests/heartbeat_goal_loop_terminal_unit.sh` — greps the dispatcher `case` for verb
  existence; now reads `src/task/*.sh` too.

`.github/workflows/*` path filters use `src/**` (recursive) and needed no change;
`tests/heredoc_substitution_unit.sh` and `scripts/unguarded-probe-scan.sh` walk the
tree recursively and needed no change.

Every one of those harnesses failed **loudly** ("the anchor moved", "verb … exists")
rather than greening vacuously — which is the only reason the sweep was findable.
