## Unreleased — test(gate): the lead-hold harness waits on a busy store instead of aborting (DIVE-4461)

`tests/gate_lead_hold_marking_unit.sh` read and wrote the fixture store with a bare
`sqlite3` — no busy timeout — while its own fixture shortens the gate hold to one
second, so the three detached deliverer children wake and write in the middle of the
fixture block. On a loaded runner the collision returned `database is locked (5)` and
`set -e` killed the run in `prepare` with nothing graded: twice on 2026-09-13, the
second time inside a merge group, where it ejected a PR a verifier had already graded
PASS and which its author cannot re-run. The helper now uses the same
`sqlite3 -cmd ".timeout 5000"` the product's own `db()` uses, and a new fixture arm
manufactures the contention so a future edit that drops the timeout reds one arm
instead of returning to a green-on-an-idle-box flake.
