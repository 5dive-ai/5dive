## Unreleased — fix(skills): the nightly skill refresh no longer counts a codex seat as "awaiting first boot" (DIVE-6148)

`5dive-refresh-skills.sh` skipped every seat whose `~/.claude` was missing, as "not booted
yet". That guard exists for claude seats, whose skills install under `~/.claude`. A codex,
opencode or pi seat installs to `~/.agents/skills`, which the add creates itself, and may
never grow a `~/.claude` at all. One codex seat ran three weeks with no default skills while
every nightly summary said `1 awaiting first boot`, so nobody looked.

The guard now applies only where the seat's skills dir is under `~/.claude`. The script asks
the CLI through a new hidden primitive, `5dive agent _skills_install_dir <name>`, which reads
the type from the registry and the dir from `skills_install_dir`, so the type map is not
copied into the script. Every other seat is refreshed from its first night and lands in
changed, first-install or failed. A bundle too old to answer keeps the old guard.
`skills_install_dir` with an empty type now returns the `.claude/skills` fallback. Before,
it printed nothing.

`tests/refresh_skills_never_booted_guard_unit.sh` runs the real script against a stubbed
bundle and `getent`. Its arms: a codex seat with no `~/.claude` is attempted; a claude seat
with no `~/.claude` is still skipped; an old bundle keeps the guard; and a mutation that
restores the pre-fix guard brings back "awaiting first boot" for the codex seat.
