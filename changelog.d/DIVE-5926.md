## Unreleased — fix(bug): `5dive bug --file` sends to 5dive's API with the box key, only after the owner says yes (DIVE-5926)

`5dive bug --file` used to open a public GitHub issue through the gh wrapper. A box with no
GitHub key saved the report and nothing ever sent it, and a box with one opened a public
issue its owner never agreed to.

- **Destination.** `--file` now POSTs the same allowlisted payload to the 5dive API
  (`/server/bug-reports`), authenticated with the box's own key. No GitHub route is left.
- **The owner says yes first.** With no TTY, `--file` requires `--owner-approved` and refuses
  without it, telling the agent to ask its owner in one line naming what failed. A TTY still
  gets the y/N prompt. The failure hints and `5dive bug --help` say the same: preview
  freely, send only after the owner agrees.
- **No nagging.** The preview records each ask, keyed by verb, exit code and the normalised
  first line of `--what`. The same defect again prints "your owner was already asked about
  this on <date>; don't ask again", and a second defect the same day is not asked either.
- **Offline.** An unreachable API spools the payload (JSON, 0600) and the next approved
  `--file` sends it; so does a 404, so a CLI released before the API keeps its reports. Any
  other 4xx answer is not spooled. Spool files from the GitHub era (`.md`)
  are never sent.
- Nothing else changed in what leaves the box: the allowlist and the full-payload print
  before sending are as they were.
