## Unreleased — fix(task): the filing cap stops counting a customer's own work as 5dive machinery (DIVE-6652)

On a customer box, `task add` refused an ordinary customer row ("commit the digest CSS")
as "internal machinery". Its 1-in-4 window counted 6 of the last 20 rows as machinery, and
all 6 were the customer's own product work: a feed-publish gate, a leak-scan gate, a
bond-digest page, "customs unit values", a `critic-board-passed` key.

- The words `gate`, `board`, `digest`, `unit`, `cron`, `hook` and `probe` now count only in
  a 5dive compound (`merge gate`, `task board`, `gate digest`, `unit test`, `pre-commit hook`,
  `selfcheck probe` and similar), never bare.
- A row filed with `--customer` is recorded as such, and the window never counts it as
  machinery again, so one filer's escape no longer raises the count for the next filer.
- `task need` on a done or cancelled row no longer says "reopen it", since no reopen verb
  exists. It now tells you to file a follow-up row with `--parent=<row>` and gate that one.
