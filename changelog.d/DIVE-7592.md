## Unreleased — fix(hermes): a Hermes agent no longer stalls on Hermes' own approval dialog (DIVE-7592)

A Hermes agent stopped answering the first time its model ran a command Hermes
calls dangerous, such as `python3 -c …`. Hermes showed its "Dangerous Command"
Allow/Deny dialog in the agent's window, and nobody is at that window on a 5dive
server, so tasks, heartbeats and messages waited until someone attached. This
turned main's nightly init-smoke red, and it had already failed the v0.113.0
release cut.

`bin/5dive-agent-start` now starts a Hermes seat in Hermes' own approve-all mode
(`HERMES_YOLO_MODE=1`, what `hermes --yolo` sets), as grok (`--always-approve`)
and antigravity (`--dangerously-skip-permissions`) already run. The seat's Linux
user and tier stay the limit, and Hermes still blocks its hardline commands
(`rm -rf /`, `mkfs`, …) and anything in `approvals.deny`. The variable is set only
in the agent's own window, so the Hermes messaging gateway keeps its Telegram
approval buttons.

`tests/dive7592_hermes_approve_all_unit.sh`: 8 arms, including the failing run's
exact command against a real Hermes install (it raises the dialog without the
switch, and runs with it).
