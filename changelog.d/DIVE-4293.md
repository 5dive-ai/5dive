## Unreleased — fix(agent): a headless seat can no longer stop on a question nobody can answer (DIVE-4293)

`bypassPermissions` skips **permission** prompts. `AskUserQuestion` is not one — it is a tool the
model calls on purpose, and nothing in `permissions.deny`, no hook and no liveness rule touched it
on a seat with no paired channel. The only guard that existed (`hooks/pretool-question.ts` +
`lib/question-bridge.ts`) ships **inside the telegram plugin**, so it is installed exactly where a
human can already be reached and absent exactly where nobody can answer. `cmd_doctor.sh` records
the fold that removed the standalone hook from headless seats.

Measured 2026-09-11: dev2, fenced by the heartbeat `/goal` to "Work ONLY this one task", took two
admin pings ("gate cleared — resume the task"), read the fence and the pings as a conflict, and
opened a four-option chooser. The pane sat at `Enter to select` from ~05:40Z until a human noticed
at 07:12Z — **92 minutes** — with two rows' finished, committed work waiting on a push the gate had
already cleared.

- **`hooks/pretool-headless-question.sh`** denies `AskUserQuestion`/`ExitPlanMode`, wired by
  `preseed_claude_agent` into the per-agent `settings.json` **only when the seat has neither
  telegram nor discord**. Both halves are load-bearing: a telegram seat already carries the
  plugin's deny and two would double-fire, and "No human sits at this keyboard" is only *true*
  where this one is installed. The refusal routes a choice that genuinely needs a person to
  `5dive task need` — without that the deny is a dead end and the next model reasons its way back
  to the picker.
- **A supervisor class `blocked-on-prompt`**, not a liveness one: `cmd_liveness.sh`'s charter
  refuses pane scrapes, and supervisor's signals are the ones kept for remediation. Deliberately
  **outside** the `stuck` ladder — `nudge` types a line into a pane waiting for a *key* and
  `resume` presses Escape, which discards the question. It auto-answers with Enter **only** when
  the HIGHLIGHTED option carries `(Recommended)` (Enter takes the cursor's option, so the cursor
  read is the whole safety argument) and otherwise pages on its own alert. The 12-line tail window
  is the false-positive control, not a perf choice: agents *write* this string — this entry does —
  and the 40-line window the verify/quota probes use would classify any seat discussing a picker as
  sitting on one.
- **The `/goal` template** says a gate-cleared ping about another row you own with finished work is
  not a scope conflict, and that there is no human at this keyboard. The fence caused the question.

`tests/headless_question_guard_unit.sh` is 33 arms. The install-gating arm **extracts and executes**
the shipped `jq` filter against a settings object that already carries `SessionStart`, so a filter
replacing `.hooks` wholesale reds rather than silently dropping resume-context from every headless
seat; arm 4 strips the install and the channel-less arm must red.

Not covered, signed rather than hidden: no fresh-seat `agent create` end to end (`preseed_claude_agent`
needs root and a real agent home), and the root `capture-pane` hop is unexercised — only its pure
cores are graded, the same split as the verify/quota probes beside it. `_SUP_PROMPT_PAT` is inferred
from the incident and env-overridable via `SUPERVISOR_PROMPT_PAT`.
